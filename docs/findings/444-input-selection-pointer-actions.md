### State flow and boundaries

`InteractionActionCodeMapInitialize` builds the action-code lookup used by input consumers. Pointer input enters through `SimulationPointerActionDispatch`, which resolves interface/cell hits and eventually calls `UiActionDispatch`; that dispatcher routes numeric actions to selection, entity-command, UI-mode, and queued-request helpers. The selection helpers share coordinate and mode globals, with the cancellation paths converging on `SelectionClearRequestAndHudReset`. `StoreSelectedMapCoordinate` writes the current coordinate to `DAT_004ddcc4/0x004ddcc8` and stages the same pair at `DAT_004ddcf4/0x004ddcf8`; it stores the current mode in `DAT_004ddccc` and pending mode in `DAT_004ddcfc`. When `EventTimerCountdownAdvance` completes its transition, it copies the staged coordinate and mode into the current fields. The binding getters provide another input path: pressed-state and bit-3 checks select configured values before an action is dispatched. These links are directly visible in calls and global reads/writes; the intended names of many numeric modes and flags remain inferred or unknown.

The debug-input routine is a separate edge-triggered path: it compares current and prior input globals, then calls camera, level, object, and mode helpers. The body establishes the mutations and callees, but does not fully establish which physical keys or user-facing options each global represents.
