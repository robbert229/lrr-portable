# Finding 200 — Configured Video Polls a DirectShow Sample

After opening a configured video, the game creates a DirectDraw stream sample, obtains its surface, and starts the multimedia stream with state value `1`. Its update callback then calls `IStreamSample::Update(0, NULL, NULL, NULL)`. Only an `S_OK` result reaches the next virtual call; any other result enters cleanup and returns false. This is a synchronous sample-polling path, matching the loop shape in Microsoft's DirectShow video-streaming sample. The following virtual call's interface identity and exact presentation behavior are not established here.

**Evidence.** In `reference/LegoRR.exe` (SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`), `FUN_004721e0` (`0x4721e0`) queries the primary video stream for `IDirectDrawMediaStream`, calls its `CreateSample` slot at vtable offset `+0x34`, gets the sample surface through offset `+0x20`, queries the surface interface, then calls the multimedia stream with state `1`. `FUN_004724a0` (`0x4724a0`) calls `Update` through sample slot `+0x18` with all zero arguments; the `iVar2 == 0` branch gates a second call, while the other branch releases several interfaces and returns false. Microsoft's [DirectShow sample](https://learn.microsoft.com/en-us/windows/win32/directshow/video-streaming-sample-code) uses `SetState(STREAMSTATE_RUN)` followed by a loop while `IStreamSample::Update(0, NULL, NULL, NULL) == S_OK`; its [multimedia-stream guidance](https://learn.microsoft.com/en-us/windows/win32/directshow/using-multimedia-streams-in-applications) describes that run/update sequence.

This static trace does not establish the runtime cadence or whether a particular video reaches end-of-stream normally.
