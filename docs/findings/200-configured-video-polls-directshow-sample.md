# Finding 200 — Configured Video Pumps and Blits DirectShow Samples

After opening a configured video, the game creates a DirectDraw stream sample, obtains its source surface, and starts the multimedia stream with state value `1`. Its update callback calls `IStreamSample::Update(0, NULL, NULL, NULL)`. When that returns `S_OK`, the game calls `IDirectDrawSurface3::Blt` on the supplied destination surface, copying the whole sample surface with `DDBLT_WAIT`. The callback returns true only if both calls return zero. Any other sample-update result enters interface cleanup; a failed blit also returns false. This is the synchronous sample-and-blit loop shape in Microsoft's DirectShow video-streaming sample, with the frame copy made explicit.

**Evidence.** In `reference/LegoRR.exe` (SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`), `FUN_004721e0` (`0x4721e0`) queries the primary video stream for `IDirectDrawMediaStream`, calls its `CreateSample` slot at vtable offset `+0x34`, gets the sample surface through offset `+0x20`, queries it for `IDirectDrawSurface3`, then calls the multimedia stream with state `1`. Constructor call-site `FUN_00472560` (`0x472560`) passes the queried game surface into wrapper field `+0x1c`. In `FUN_004724a0` (`0x4724a0`), sample slot `+0x18` is called with four zero arguments. Its zero-result branch calls destination-surface slot `+0x14` with destination rectangle `NULL`, source surface from field `+0x14`, source rectangle `NULL`, flags `0x01000000`, and effects pointer `NULL`; the other branch releases several interfaces and returns false. The interface slot and five-argument signature match `IDirectDrawSurface3::Blt`; Microsoft documents `DDBLT_WAIT` as waiting until the blit can be set up or another error occurs. Microsoft's [DirectShow sample](https://learn.microsoft.com/en-us/windows/win32/directshow/video-streaming-sample-code) uses `SetState(STREAMSTATE_RUN)` followed by a loop while `IStreamSample::Update(0, NULL, NULL, NULL) == S_OK`; its [multimedia-stream guidance](https://learn.microsoft.com/en-us/windows/win32/directshow/using-multimedia-streams-in-applications) describes that run/update sequence, and the [DirectDraw Blt reference](https://learn.microsoft.com/en-us/previous-versions/ms785070%28v%3Dvs.85%29) describes the blit parameters and wait flag.

This static trace does not establish the runtime cadence or whether a particular video reaches end-of-stream normally.
