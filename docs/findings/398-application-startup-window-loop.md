# Finding 398 — Application Startup, Window Loop, and Preferences

This slice covers the Win32 process entry, startup configuration, window state and message handling, and two frame-pump paths. The evidence is the named Ghidra pseudocode and direct callsites in [`LEGORR.full.c`](../decompiles/full/LEGORR.full.c); flag meanings are kept qualified where the code does not establish them. Callback relationships are identified as inference where only the function pointer or call order is visible.

## Lifecycle and neighboring systems

`WinMain` is the hub: it reads startup parameters, invokes `CommandLineOptionParse`, mounts resources and initializes input, creates the window, then calls renderer/device setup before entering the callback loop. The callback triplet is the application/game boundary: the first callback can veto continued startup, the second receives the frame delta, and the third runs on the shutdown path. This interpretation is supported by call order and argument use, but the callback type contract is not declared in the pseudocode.

The separate `MainLoopFramePump` is used by modal or blocking UI/video/loading paths and performs a similar pump without invoking the registered update callback. Both paths share the Win32 queue drain and input/cursor/frame helpers. Window messages update globals that are polled by input/game code; the precise semantic mapping of several globals remains unknown.

Startup preferences are split between the `StandardParameters` registry/config value and command-line switches. The code concatenates the selected parameter value with the command line before parsing, so the parser's effective input is not just `GetCommandLineA()`. The option bits feed later startup, display-mode, audio, animation, and rendering paths; this finding does not assign undocumented names to the full flag word.

## Open questions and follow-up slices

- Determine whether `DisplayDeviceCapsQueryDiscard` should release the DC, and whether the current behavior is a leak or a platform-specific convention.
- Trace the runtime flag bits through their consumers before assigning stable semantic names; in particular bits `0x2`, `0x20`, and `0x40000` have multiple writers/readers in this slice.
- Document the exact `StandardParameters` source and option precedence, including how parsed flags map to the public startup/configuration behavior.
- Identify the callback triplet's registration sites and concrete init/update/shutdown implementations, then turn any confirmed behavioral gaps into focused implementation issues.
