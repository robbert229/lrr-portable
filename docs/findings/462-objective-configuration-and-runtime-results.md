# Finding 462 — Objective Configuration and Runtime Results

The assigned objective functions load per-level objective data and HUD text, arm individual objective tests in a shared level record, and publish result state for the later objective state machine. Direct mechanics are visible in [`LEGORR.full.c`](../decompiles/full/LEGORR.full.c); Finding 22 already maps most of the objective flag bits and their consumers. This finding records the assigned entry points and links those configuration writes to the runtime result path without treating numeric result codes as broader game semantics.

## Level setup and HUD text

`ObjectiveConfigLoad @ 0x00457d40` clears 21 dwords beginning at level-record offset `+0xbc` and resets the shared objective/advisor flag word `_DAT_004ffbc0` and `DAT_004ffe34`. It reads the three `DontShowObjective*Advisor` switches into suppression bits `0x10`, `0x20`, and `0x80`; resolves optional objective/completion/failure image definitions and AVI data into the level record; then loads the objective targets. `CrystalObjective` and `OreObjective` are parsed and passed to `ObjectiveCrystalOrOreArm @ 0x00458580`; `TimerObjective` is converted from seconds to ticks by multiplying by 25 and passed with a `HitTimeFailObjective` comparison result to `ObjectiveTimerArm @ 0x004585f0`; `ConstructionObjective` is parsed to two indices and passed to `ObjectiveConstructionArm @ 0x00458620`; and `BlockObjective` is parsed into a two-word pair passed to `ObjectiveBlockArm @ 0x004585c0`. It finally delegates `ObjectiveText` to `ObjectiveTextOverlayLoad @ 0x004574e0`. If none of the suppression flags was set during config parsing, it sets `0x10` by default. The detailed flag map is in Finding 22.

`ObjectiveTextOverlayLoad @ 0x004574e0` releases old text surfaces, creates new surfaces for objective/completion/failure sections, opens the supplied text resource, parses section headers, and renders recognized sections (`Objective`, `Completion`, `Failure`, and `CrystalFailure`) into their matching surfaces. It processes `\\a` and `\\n` sequences in the text body and optionally loads `MissionBriefingText`, `MissionCompletedText`, and `MissionFailedText`, replacing underscores in those configured strings with spaces before drawing. The parser's recognized section names are directly visible; the authored text format's full grammar is not established here.

The arm helpers write their target fields and flags: `ObjectiveCrystalOrOreArm @ 0x00458580` stores nonzero crystal/ore targets at `+0xf4`/`+0xf8` and sets `0x100`/`0x200`; `ObjectiveBlockArm @ 0x004585c0` stores two words at `+0xfc`/`+0x100` and sets `0x400`; `ObjectiveTimerArm @ 0x004585f0` stores the tick count at `+0x104` and sets `0x800`, also setting suppression bit `0x20` when the mode argument is nonzero; `ObjectiveConstructionArm @ 0x00458620` stores two values at `+0x108`/`+0x10c` and sets `0x1000`. These helpers do not evaluate whether an objective has been met.

## Result publication and aliases

`GlobalFlagGet_004ffe30 @ 0x00458650` returns `DAT_004ffe30`; `GlobalValueSet_004ffe48 @ 0x00458660` writes its argument to `DAT_004ffe48`. Their names describe only those direct global operations. `ObjectiveVoiceAliasPrepare @ 0x00458670` uses its argument as a result selector: 0 sets pending bit `0x1`; 1 records achieved (`0x2`), sets `DAT_004ffe30` to 1, records result index 1, and starts the completion path; 2 records failed (`0x4`), sets the global result to 0, and records index 2; 3 records the crystal-failure combination (`0x104`) and index 2. It sets the shared “result announcement pending” bit `0x8`, updates related scene/state helpers, and—when the corresponding overlay/state gate is enabled—builds a stream alias from `Acheived`, `Failed`, or `FailedCrystals`. The alias is stored in `DAT_004ffe38` for later handling. Finding 22 traces the downstream state machine and advisor suppression behavior; the stream alias’s eventual playback is outside this assigned set.

The config loader is called from `LevelLoad @ 0x00429890` (site `0x0042ab0a`, Finding 22); that loader also calls `GlobalValueSet_004ffe48 @ 0x00458660` to set the global value from level state, and calls `ObjectiveVoiceAliasPrepare(0)` to initialize the pending result state. `GlobalFlagGet_004ffe30 @ 0x00458650` is consumed by `SaveMenuOpenFromReward @ 0x00462030` to gate its reward/save menu path. Representative result-helper callers are `ObjectiveVoiceAliasRaiseCommit @ 0x00454b70` (mode 1), `ObjectiveVoiceAliasRaiseGateBit27 @ 0x00454b80` (mode 2 when global bit `0x08000000` is clear), `AirSupplyAmountUpdate @ 0x00424560` (mode 2 when air supply expires), `MainSimStep @ 0x004250c0` (mode 3 on its crystal-failure branch), and `ObjectiveTick @ 0x00458be0` (mode 1 or 2 after its objective checks); the latter is the per-frame state-machine path. `ObjectiveVoiceAliasPrepare` also invokes the related state/scene helpers described in Findings 258 and 389. Finding 22 documents how the objective checker and frame-driven outcome state machine consume the result bits and pending advisor flags.

## Limits and follow-up

These functions establish config key handling, target storage, flag writes, text-section parsing, and result/alias selection. They do not identify the complete authored objective text grammar, the semantic units of each objective pair, or every downstream audio/video resource consumer. Existing findings already trace the objective checker and per-frame state machine, so no duplicate implementation issue is needed here. A useful follow-up would validate the text/alias parser against a set of shipped level files and enumerate outcome alias consumers; that data-level verification is beyond the assigned function bodies.
