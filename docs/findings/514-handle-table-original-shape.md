## Boundary and state

The dossier for `00488b50`–`00489c30` shows the preceding sound unit's last
functions accessing its `00544a1c` field, followed immediately by these four
functions accessing `00544a20`–`005488a4`. The first two walk the same
8-byte records; the other two index them. The next unit's first function
accesses `00505914`, not the table, and the following functions do not
reference the table. This data step supports the mapped boundary; ordinary
16-byte function alignment and NOP padding cannot establish it (finding 505).
The next unit is not required by these leaf functions.

The static table contains exactly 2,000 records: pointer and flags, eight
bytes on the 32-bit matching build, occupying `00544a20`–`005488a0`
(exclusive). `005488a4` is the loop's one-past flags address, not an extra
record. Native pointer-sized records grow on 64-bit hosts, so no sidecar is
needed. Reset clears without freeing; allocation uses the engine heap and
sets flag bit 0; release frees and clears; lookup checks bounds and the bit.
The original 2,000-entry size is retained without a scoring-only spare slot.

The reset and allocation instructions match the original except for the
loop-end immediate: Reccmp cannot associate `005488a4` (four bytes beyond
the table's end) with the annotated variable, so compares the unrelocated
addresses. The instructions and lengths otherwise match. Enlarging the table
to improve the score would distort per-object data layout needed by #388.

## Callers and entropy

Existing callers keep their signatures, now with C linkage. All mapped
callers retain their scores; the full gate found no caller drop or rise.
Across both scopes, four functions rise, one outside function falls and none
are newly mapped or lost. The sum of score changes is +103.55 percentage
points across common functions.

The sole drop is `terrain_cell_normal_sample` (`004512d0`), 11.22% →
10.31%. Its source is unchanged. Single-function builds of the before and
after trees produce 100 → 99 instructions. A direct comparison of their
recompiled listings shows a hoisted `lea edx,[ecx+0xc]` removed; loads use
`[ecx+0x10]` and `[ecx+0x14]` directly, two commutative x87 additions swap
operands, and one temporary changes `esi` to `edx`. Branch displacements
change by three bytes. This is allocation/scheduling drift consistent with
ADR 0005 rule 2, rather than a source change. **Owner exception:** the
instruction count changes by −1. PR #427 documented the reverse hoisted-`lea`
drift for the same function.

## Validation

The native CMake build and all 32 tests, including `c_boundaries`, pass. The
new C source also passes `gcc -std=gnu89 -Werror=declaration-after-statement
-fsyntax-only`. `translation_units.py build` regenerated the map with no data
conflicts. The matching gate was reviewed against the old baseline before
refreshing it; the refreshed baseline and binary progress are generated by
`make match-progress`.

Whole-binary progress before → after: full accuracy 54.07% → 54.12%,
game-only accuracy 49.74% → 49.79%, exact-function bytes 40,883 → 40,972,
and `.text` bytes identical at original addresses 18,260 → 17,960. The last
figure compares fixed addresses and is sensitive to link layout.
