# Finding 456 — World Entity Creation and Pointer Registries

The 11 procedures assigned by issue #155 cover entity-backed commands, object construction, cell-to-object bookkeeping, per-entity tables, and a bounded pointer registry. The decompile establishes the record offsets, calls, and conditions below; names like “cell object” follow the caller behavior, while opaque flags and record fields remain numeric.

## Creation and registration flow

`WorldObjectCreateWithTransform` prepares a stack record and delegates to `FUN_00409b30`, which creates a type-4 entity through `FUN_00438610`. Its optional flag path sends event 8. The supplied pair array feeds two paths: a nonfinal coordinate entry equal to the following entry calls `FUN_00432490` and `FUN_00440130`; differing adjacent entries or the final entry enter the cell/update sequence, whose callee choice depends on entity flag `+0x3e4` bit `0x100000` and whose `FUN_004325d0` call is gated by bit `0x200`. `OListEntityRecordParse` and `DeferredOListEntityCreateAndLink` are observed callers of this constructor for type-4 object records; both later register selected type-`0xb` entities with `RegisterObjectAtGridPosition`.

The grid object list is maintained by `GridCellObjectLinkInsert` and its remove helpers around a free list of `0x14`-byte records. Insertion ensures the list exists, takes a record from the free list (allocating a chunk when needed), stores entity and `(x,y)`, writes it at the per-cell head, clears the cell record’s third dword, sets entity flag `+0x3e4` bit `0x2000000`, and calls `FUN_0040cea0` to update adjacent cells. `RegisterObjectAtGridPosition` reaches this helper from OList parsing, deferred object creation, and an entity type update. `CreateCellObjectIfAvailable` and `DeleteCellObject` are used by the level debug cell mutator. `CellEntityKindCreateOrRemove` is called from cell initialization after a separate predicate decides whether to create or remove the type-`0xe` entity.

The pointer registry is a distinct table from the cell-object list. `OListEntityRecordParse` clears its ten storage slots, resets count `DAT_005563e0`, and appends successfully created entities while the count is below ten. `ObjectPointerRegistryClearMatch` is called by entity teardown. `ObjectPointerRegistryGetSlot` supplies indexed pointers to camera/effect routines, including `CameraFocusTweenUpdate` and the callback at `FUN_00454600`; its result is checked before dereferencing the object. This establishes a bounded pointer-slot table populated with created entities; teardown can leave null slots without compacting the counted range. The slot-to-object assignment policy is otherwise unresolved.

`EntityTableMapsAllocate` runs during `GameConfigInit`, after the entity-type counts have been established. `ResourceHandleSetRelease` releases the six allocations, and `LevelStateCountersClear` zeros their entries; separate writers/readers determine how the arrays are used. `EntityKindCommandIssue` is reached by UI action dispatch and the main simulation interaction handler. Its entity bit prevents duplicate kind-`0x12` commands while one is pending; the entity flag tests and resulting command field values are retained as numeric evidence.
