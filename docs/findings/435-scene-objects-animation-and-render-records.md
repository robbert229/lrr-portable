# Finding 435 — Scene Objects, Animation, and Render Records

This investigation ties together the assigned scene-object, animation, renderer-record, and presentation helpers. Function behavior below follows checked-in pseudocode; linked findings provide caller/evidence context where available. I mark interpretations as inferences and leave field meanings unresolved where pseudocode does not establish them. The functions form several cooperating layers: object records hold renderer handles and state; animation wrappers forward time, visibility, and transform operations; list callbacks synchronize scene nodes; and higher-level routines allocate or submit transient, UI, selection, and viewport rendering work.

## Object records and renderer handles

`SceneObjectModeIsOne @ 0x00406980` tests the dword at object offset `+0x28`. `SceneObjectFlagsGet @ 0x00408850` reads `+0x70`, while `SceneObjectScalarAdjustByDirection @ 0x004082e0` adjusts `+0x80`, clamps the result at zero, and sets bit 1 at `+0x148`. `SceneObjectRecordCloneRetainHandles @ 0x00408620` copies `0x53` dwords, clears destination bit 0 at `+0x148`, and retains the primary handle at `+4` plus the optional secondary handle at `+0x7c`.

`SceneObjectPairApplyMode @ 0x00408670`, `SceneObjectPairSetRenderParameters @ 0x004086c0`, and `SceneObjectPairSetCallbackScalar @ 0x00408710` apply a mode, render parameters, or callback-derived scalar to the primary handle and, when present, the secondary handle. `SceneObjectIndexedHandleGetOrCreate @ 0x00408770`, `SceneObjectPrimaryHandleGetOrCreate @ 0x004087b0`, `SceneObjectSecondaryHandleGetOrCreate @ 0x004087e0`, and `SceneObjectIndexedSecondaryHandleGetOrCreate @ 0x00408810` cache resolved handles in indexed or primary/secondary slots. These relationships are consistent with records retaining one main render object and an optional companion; the exact semantic roles of the handles remain unresolved. See [Finding 373](373-cursor-simulation-renderer-and-file-helpers.md) for the operation-level traces.

Renderer records use a parallel layout. `RendererObjectUpdateFromRecordField64 @ 0x00406c00`, `RendererObjectUpdateFromRecordField68 @ 0x00406c30`, and `RendererObjectUpdateFromRecordField6c @ 0x00406c60` forward fields at `+0x64`, `+0x68`, and `+0x6c` to a shared update helper. `RendererRecordClone @ 0x00406cb0` copies 29 dwords, clears bit 0 at `+0x70`, and clones three handles and an associated object. `RendererObjectSubobjectDispatch @ 0x00406f50` creates a subobject and forwards it to a second helper. `RendererCachedHandle40GetOrCreate @ 0x00406fb0`, `RendererCachedHandle48GetOrCreate @ 0x00406fe0`, and `RendererCachedHandle50GetOrCreate @ 0x00407010` lazily populate `+0x40/+0x48/+0x50` from descriptors at `+0x2c/+0x34/+0x3c`; `RendererCachedHandle4cIsNotOne @ 0x00407040` does the same for `+0x4c` from `+0x38` and compares a helper-derived value with `1.0`. `RendererObjectTimingValueAdjustByCount @ 0x00406d30` subtracts a helper-derived duration times count minus one when count exceeds one. [Finding 365](365-renderer-record-and-cached-handle-helpers.md) has the per-function traces.

## Animation and scene transforms

`AnimationObjectVisibilitySet @ 0x00406c90` forwards a visibility request; `AnimationObjectVisibilityGet @ 0x004086a0` returns the wrapped visibility bit. `AnimationObjectTimeUpdate @ 0x00406d10` forwards a time update and `AnimationObjectTimeGet @ 0x00406da0` reads the derived timing value. `AnimationObjectTransformSet @ 0x00406dc0` forwards transform inputs, `AnimationObjectHandleGet @ 0x00406e30` returns the handle at `+4`, and `AnimationObjectValueGet @ 0x00407090` returns the wrapped value helper result. `AnimationLoopTimeAdjust @ 0x00408860` adjusts time by the cycle duration for loop iterations and may reset related animation state. [Finding 356](356-animation-and-low-address-state-helpers.md) and [Finding 277](277-low-address-helper-names.md) document these wrappers and their remaining generic semantics.

`SceneRotationFlagsApply @ 0x0040ba00` combines frame setup with animated texture-frame selection, scaling, and rotations chosen by bits 0–4. Its `SceneFrameFromTripletApply @ 0x0040bb90` callee derives an orientation from three points, positions the scene object, and installs a composed matrix. `SceneObjectListUpdateTransforms @ 0x0040fe00` updates an object and walks its linked list with two callbacks. `SceneObjectListApplyFloatCallback @ 0x0040ff50` applies a float callback to each entry; `SceneObjectListApplyPositionCallback @ 0x00410070` and `SceneObjectListApplySecondPositionCallback @ 0x004100b0` walk it with distinct position callbacks; `SceneNodePositionSet @ 0x00410020` copies a three-component position into node offsets `+0x0c/+0x10/+0x14`. `RenderNodeSetPositionFromCallback @ 0x00406df0` obtains a callback value and forwards it with coordinates to a render-node helper. See [Finding 255](255-visual-channel-relays-resource-tree-callback-walks-scene-pose-and-registry-helpers.md), [Finding 380](380-scene-objects-terrain-and-matrix-helpers.md), and [Finding 375](375-entity-ui-and-render-tree-helpers.md).

## Record creation and render submission

`SceneNodeRecordCreate @ 0x0040f6c0` allocates and initializes a `0xa0`-byte node record. `SceneObjectChainRecordCreate @ 0x00435b20` allocates a `0xbc`-byte record, creates and poses a base scene object, and conditionally attaches up to four additional objects; its callers are in `GameConfigInit`. `ModelTransformCopyToSceneNode @ 0x00435e35` copies position and rotation from the scene node into a kind-3 model record, while `RendererNodeRelativePositionSet @ 0x00436ac9` forwards relative x/y coordinates to a node helper. Details and callers are in [Findings 258](258-interface-method-wrappers-overlay-refresh-and-deferred-set-relays.md) and [372](372-incident-messages-options-and-resource-helpers.md).

The quad-mesh path starts with `EntityQuadMeshRenderRecordAllowed @ 0x0040aae0`, which rejects entities with flag `0x08000000` and kinds 8 or 13. `QuadMeshRenderRecordCreate @ 0x0040a4b0` also requires a nonzero count below 999, allocates a pool slot, initializes or reattaches a scene object and mesh, and fills its displayed count. `QuadMeshRenderRecordPoolSlotAllocate @ 0x0040a5c0` claims the first free eight-dword slot by setting bit 0 at `+0x1c`. [Findings 251](251-command-band-kind-dispatch-item-name-lookup-route-and-record-helpers.md) and [374](374-terrain-interface-and-media-helpers.md) trace the allocator, gate, and caller.

Other presentation helpers cover distinct paths: `TransientEffectRenderSlotConfigure @ 0x0040c2f0` configures a slot in one of two observed pools; `RenderUiFrameCell @ 0x00412450` draws an entry or resolves its frame descriptor before submission; `RenderTransitionCleanupIfActive @ 0x004189d0` invokes cleanup when two global bits are set and clears one bit; `SinePhaseMidpointBlendDispatch @ 0x00424730` advances a sine phase and blends stored midpoint values before dispatch; `ApplyDefaultTransformToFlaggedRenderObject @ 0x004247d0` and `ApplyDefaultTransformToFlaggedRenderObjects @ 0x00424810` apply a default transform to one flagged object or a collection. See [Findings 252](252-config-band-texture-loaders-route-commands-and-surface-menu-helpers.md), [299](299-low-address-task-interface-helpers.md), [377](377-callback-registry-and-runtime-helpers.md), [256](256-command-band-step-issuers-flag-behavior-timers-and-steering-helpers.md), and [313](313-selection-resource-and-transform-helpers.md).

## Global render state and remaining questions

`GlobalRenderRecordSetFromInput @ 0x00425d50` derives a value from its input and passes both to a helper operating on global `DAT_005560e8`. `UpdateRenderViewportState @ 0x00426250` updates viewport-related state; `RenderQualityConfigApply @ 0x004334f0` applies render-quality configuration. `SelectionRectangleRender @ 0x004293b0` converts cursor coordinates and submits a four-vertex rectangle while selection dragging is active. `RenderSurfaceSecondaryGet @ 0x004065e0` returns the shared secondary render surface used by presentation paths. Existing caller traces are in [Findings 324](324-global-state-and-record-accessors.md), [329](329-viewport-and-global-refresh-helpers.md), [247](247-config-graphics-camera-tween-and-pool-spawn-helpers.md), [292](292-selection-and-pointer-registry-helpers.md), [172](172-avi-frames-blit-to-render-target.md), and [205](205-directshow-video-uses-shared-render-presentation.md).

The cross-function evidence establishes record layouts, cached-handle behavior, callback flow, and several render submission paths. It does not resolve the semantic meaning of many record fields, global flags, renderer descriptors, or the exact ownership contract between scene nodes and their handles. Focused follow-up work should trace those fields from higher-level object creation and destruction paths, and identify callers of the viewport and quality setters beyond the current call-site records.

Complete pseudocode is in [LEGORR.full.c](../decompiles/full/LEGORR.full.c); named excerpts are in [engine-region.c](../decompiles/legacy/engine-region.c). This finding synthesizes existing address-level maps and caller evidence rather than claiming new direct evidence records.
