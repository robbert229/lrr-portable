# Finding 395 — CRT and OS File/Stream I/O

This finding maps the 39 functions assigned to `platform-and-runtime/runtime-file-streams`. Evidence is the canonical decompile corpus (`docs/decompiles/full/LEGORR.full.c`); caller/callee claims below refer to direct calls in that corpus unless marked as an inference. The CRT stream/file records are interpreted from their repeated field access patterns, and flag meanings are kept literal where not established.

## Descriptor table and Win32 handles

- `CrtFileDescriptorTableInit @ 0x004965d0` allocates a first table of 32 eight-byte descriptor slots, initializes handles to `-1`, flags to zero, and a per-slot byte to line feed. It reads inherited descriptors from `STARTUPINFO.lpReserved2`, caps the inherited count at `0x800`, and allocates additional 32-slot blocks as needed. It then installs stdin/stdout/stderr from `GetStdHandle` when not inherited and calls `SetHandleCount`. The CRT `entry @ 0x0048f000` calls it.
- `CrtFileDescriptorAllocate @ 0x00498fe0` scans the 32-slot blocks for a slot whose open bit is clear, marks its handle `-1`, and returns the global descriptor index. If it reaches a missing table block, it allocates and initializes another 32-slot block and extends `DAT_0076dec0` by 32. Exhaustion or allocation failure returns `-1`.
- `CrtFileDescriptorSetHandle @ 0x004990a0` stores a Win32 handle only into a valid descriptor slot whose handle is `-1`. When `DAT_004afd64 == 1`, descriptors 0–2 also update the matching process standard handle; stdout/stderr additionally update their initial table slots.
- `CrtFileDescriptorHandleGet @ 0x004991f0` returns the stored handle only if the descriptor is below `DAT_0076dec0` and its open bit is set; otherwise it sets the CRT invalid-handle error and returns `-1`.
- `CrtFileDescriptorCloseSlot @ 0x00499150` clears an open descriptor slot to `-1`, and optionally clears the process standard handle for descriptors 0–2. It does not itself call `CloseHandle`.
- `CrtFileDescriptorClose @ 0x00494d10` validates descriptor bounds/open state, handles aliased stdin/stdout descriptors sharing the same OS handle, closes a non-`-1` handle, clears the slot and its flags, and maps any Win32 error. `FileResourceHandleClose @ 0x0048eae0` calls it; failed opens in `Win32FileDescriptorOpen` also use it for cleanup.
- `CrtFileDescriptorFlag40Get @ 0x00498b40` returns only bit `0x40` from an open descriptor’s flag byte, or zero for an out-of-range descriptor. The stream close/write paths and standard-stream setup consult it.
- `CrtFileDescriptorFlag80SetOrClear @ 0x0049aea0` accepts only mode selectors `0x8000` (clear descriptor bit `0x80`) and `0x4000` (set bit `0x80`), returning `0x4000` or `0x8000` according to the previous state. `Win32FileDescriptorResize @ 0x0049a890` saves and restores this mode around its zero-fill extension writes.
- `Win32FileDescriptorOpen @ 0x00499240` translates CRT access/share/create/attribute flags into `CreateFileA` arguments, allocates a descriptor, creates the OS handle, rejects invalid file types, records descriptor flags, and returns the descriptor number. It also performs append/text-mode setup through seek/read/resize helpers. `StdFileOpen @ 0x00494e30` calls it.
- `Win32FileDescriptorSeek @ 0x00496c00` validates an open descriptor, resolves its handle, calls `SetFilePointer`, maps Win32 errors, clears descriptor bit `0x02` on success, and returns the new file position or `-1`.
- `Win32FileDescriptorResize @ 0x0049a890` preserves the current position, measures end-of-file, truncates with `SetEndOfFile` when the target is smaller, or writes zero-filled chunks of up to `0x1000` bytes to extend it, then restores the prior position and mode flag. `Win32FileDescriptorOpen` uses it when establishing append behavior.
- `Win32ErrorMapToErrno @ 0x00496ee0` stores the original Windows error in `DAT_005490d4`, searches the CRT’s error translation table at `DAT_004b24c0`, then applies fallback mappings for selected ranges. Descriptor close/seek/read/write and several filesystem callers use it.
- `CrtFindHandleClose @ 0x0048f950` wraps `FindClose`; failure sets the CRT error global to `0x16` and returns `-1`, success returns zero. `WadMountStartup @ 0x0047f130` and `DirectoryTreeScan @ 0x00480390` call it.

The descriptor records are organized in blocks of 32, with a handle dword and flag/state bytes at offsets `+4` and `+5`. This layout is direct from table initialization and descriptor access; interpreting every flag bit as a particular CRT mode requires additional cross-references.

## OS-level read, write, seek, and stream buffering

- `Win32FileDescriptorRead @ 0x00497130` validates an open descriptor and calls `ReadFile`. It may prepend a saved byte from descriptor state, translates CRLF to LF in text mode, retains a trailing CR/lookahead byte for the next call, and sets an EOF flag when Ctrl-Z is encountered under the applicable mode. It returns translated byte count, zero at EOF, or `-1` after mapping an OS error. `CrtStreamReadByte`, `GameFileReadBuffered`, and `Win32FileDescriptorOpen` call it.
- `Win32FileDescriptorWrite @ 0x00496cc0` validates the descriptor and writes binary data directly. For text-mode descriptors it expands LF to CRLF in bounded temporary chunks and adjusts the returned count to exclude inserted CR bytes. A zero-byte write returns zero; a special descriptor mode treats an initial Ctrl-Z as end-of-file; other failures are mapped to CRT errors. Stream flush, stream write, game-file write, and resize paths call it.
- `CrtStreamReadByte @ 0x00497040` checks stream readability/EOF flags, transitions the stream into read mode, allocates a buffer when needed (or uses its existing buffer), calls the descriptor read helper for `stream[6]` bytes, and returns the first byte while retaining the rest in the stream buffer. It sets EOF/error flags for zero or failed reads and grows a standard buffer from `0x200` to `0x1000` in one descriptor mode. `GameFileReadBuffered` and the byte/line wrappers call it.
- `BufferedStreamGetByte @ 0x0048fe20` and `ScanStreamGetChar @ 0x00494c70` consume a byte from the stream buffer when available and otherwise refill through `CrtStreamReadByte`. They are direct consumers in game-file reads and formatted scanning, respectively.
- `BufferedStreamReadLine @ 0x0048fe50` reads at most `size-1` bytes, stops after LF, NUL-terminates, and returns null only for an invalid nonpositive size or EOF before reading any byte. `GameFileReadLineDispatch @ 0x0047fd40` calls it.
- `CrtFlushStreamBuffer @ 0x0048fd20` writes pending output bytes when stream flags indicate a buffered write stream, clears the buffer pointers/count, and sets the stream error bit if the descriptor write is short. `FileResourceHandleClose`, `FileResourceHandleSeek`, `GameFileWrite`, and the buffer-release helper call it.
- `CrtFileStreamClose @ 0x004908a0` is the slow path called when a buffered character write fills or transitions the stream. Despite the assigned alias, this body does not close the descriptor: it validates stream flags, allocates a buffer if needed, writes a byte directly or drains buffered bytes through `Win32FileDescriptorWrite`, updates stream pointers/counts and error flags, and returns the written byte or `-1`.
- `CrtBufferedCharacterWrite @ 0x00491360` writes a byte into the current stream buffer when space remains, otherwise calls `CrtFileStreamClose`; it increments an output count or sets it to `-1` on failure. `EngineFormatStringToStream @ 0x004909d0` uses it directly and through repeated-character/string helpers.
- `CrtWriteRepeatedChar @ 0x004913b0` emits a requested character repeatedly through `CrtBufferedCharacterWrite`, bounded by count and stopping on error.
- `CrtWriteStringBounded @ 0x004913f0` passes up to the specified number of source bytes, one by one, through `CrtBufferedCharacterWrite`, stopping on output error. The visible loop does not stop at a NUL byte; its bound is the controlling length.
- `CrtStandardStreamBufferInstall @ 0x004974d0` installs a shared 0x1000-byte buffer for the recognized standard output/error stream records when their descriptor passes the flag-`0x40` check and the stream has no existing buffer. It sets buffer pointers/count and stream flags; allocation failure returns zero. `CrtInputWithStreamBufferSetup` is its caller.
- `CrtStreamBufferFlushAndRelease @ 0x00497570` flushes a stream when its buffer flags request it. With its first argument nonzero, it also clears buffer capacity/pointers and buffer-related stream flags after flushing. `CrtInputWithStreamBufferSetup` calls it after the formatting routine.
- `CrtStreamBufferAllocate @ 0x00498ae0` allocates a 0x1000-byte buffer and configures stream pointers/flags; on allocation failure it installs the stream’s inline two-byte buffer and marks the small-buffer state. Read, pushback, and stream-write paths call it.
- `CrtOwnedStreamBufferRelease @ 0x00494df0` frees the buffer at stream field 2 only when the stream flags indicate both a supported stream kind and owned allocation, then clears buffer flags and pointers. `FileResourceHandleClose` calls it.
- `CrtInputWithStreamBufferSetup @ 0x0048fed0` performs standard-stream buffer setup, calls `EngineFormatStringToStream @ 0x004909d0` with its arguments, then flushes/releases through `CrtStreamBufferFlushAndRelease`. The assigned name suggests input, but the observed callee is the output formatter; the role/name mismatch should remain explicit until broader call context resolves it.
- `Win32FileDescriptorSeek @ 0x00496c00` clears a descriptor state bit after a successful seek; stream seek callers also flush buffered output before changing position. This links stream state to OS descriptor state.

## Formatted input and pushback

- `VsscanfParseInput @ 0x00490070` constructs a local byte-stream record around a caller-provided string and calls `CrtFormattedScanV @ 0x00493ef0`; `FileTokenListLoadAndTreeScan @ 0x004802d0` calls it.
- `CrtFormattedScanV @ 0x00493ef0` parses a scanf-style format against the stream abstraction. It skips classified whitespace, handles literal matching and format width/suppression/length flags, and has paths for character/string/scanset, signed/unsigned/octal/hex/pointer, floating-point, and `%n` conversions. It uses `ScanStreamGetChar`, `StreamPushbackChar`, `StreamSkipClassifiedChars`, character-classification helpers, and multibyte conversion; it tracks consumed characters and successful assignments and returns the assignment count (or `-1` for input failure before a conversion). `VsscanfParseInput` and `MarkupIntegerTokenParse @ 0x0048e890` call it.
- `CrtScanFormatCharNormalize @ 0x00494c30` leaves decimal digits intact and maps non-digit format/input characters by case-normalizing and subtracting the alphabetic offset, which makes letters usable as hexadecimal digit values. `CrtFormattedScanV` calls it in numeric parsing.
- `StreamPushbackChar @ 0x00494ca0` ignores EOF (`-1`) and otherwise delegates to `CrtStreamUngetByte @ 0x00498f50`.
- `StreamSkipClassifiedChars @ 0x00494cc0` reads one character and continues while `FUN_00498f00` classifies it as whitespace, incrementing the consumed-character count; the first nonspace is returned to the caller.
- `CrtStreamUngetByte @ 0x00498f50` accepts a byte only for streams in read mode or a permitted special state, ensures a buffer exists, moves the read pointer backward and increments the available-byte count. Under descriptor flag `0x40`, it only pushes back a byte if it matches the preceding buffer byte; otherwise it restores the pointer and fails.
- `FormatArgumentReadDword @ 0x00491430`, `FormatArgumentReadWord @ 0x00491470`, and `FormatArgumentReadDouble @ 0x00491450` advance a caller-supplied varargs cursor by 4, 4, and 8 bytes, respectively, returning the corresponding argument value. They are called by `EngineFormatStringToStream` for width/precision and value arguments.
- `CrtScanfNumericConversionAssign @ 0x00498ce0` converts a parsed numeric token according to conversion/length metadata, uses CRT numeric conversion and assignment helpers, then releases its temporary token. Its direct callers in the corpus are CRT floating-point conversion paths; a direct call from `CrtFormattedScanV` is not shown, so the wider relation between these parsing implementations remains unresolved.

## Error and state flow

- Descriptor operations validate the open bit before touching a handle. Invalid descriptors set CRT error `9`; `Win32ErrorMapToErrno` preserves the raw Windows error separately and maps it to the CRT error global.
- Read/write/seek return conventions differ by layer: descriptor read returns `-1` on error and zero at EOF; buffered stream reads also return `0xffffffff` for EOF/error with flags carrying the distinction; short writes set the stream error flag.
- Text-mode newline translation is performed by descriptor read/write helpers, while stream functions manage buffers and stream flags. This separation is direct from the call graph and is important when tracing byte counts or seeking.
- Descriptor state lives in global table blocks; `DAT_0076dec0` is the descriptor upper bound/count. Stream state is separate and includes buffer pointers, counts, descriptor number, and flags. The precise meaning of all stream flag bits is not fully recoverable from these functions alone.

## Open questions and follow-up slices

1. Reconcile the assigned names `CrtFileStreamClose @ 0x004908a0` and `CrtInputWithStreamBufferSetup @ 0x0048fed0` with their observed write/format behavior and wider callers.
2. Trace every descriptor and stream flag bit across initialization, open, read, write, seek, close, and standard-stream installation; confirm which bits correspond to text mode, EOF, ownership, buffering, and append.
3. Establish the exact `STARTUPINFO.lpReserved2` descriptor inheritance layout and maximum-count handling, including whether the `0x800` cap is an entry count or byte-related cap.
4. Compare `CrtFormattedScanV` conversion cases and `CrtScanfNumericConversionAssign` callers to determine whether they belong to separate scan implementations or are connected by indirect paths.
5. Check partial writes and text-mode CRLF conversion when the OS writes only part of a translated chunk; the helper returns translated counts but no test evidence is part of this investigation.
6. Trace the CRT error translation table contents and all fallback ranges in `Win32ErrorMapToErrno`.
7. Establish lifecycle for shared standard stream buffers at `DAT_005493e8`, including whether they are process-lifetime or freed at shutdown.
