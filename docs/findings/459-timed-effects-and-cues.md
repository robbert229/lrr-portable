# Finding 459 — Timed Effects and Cues

The assigned functions implement a slot-based overlay cue system. Request helpers update per-slot state in a fixed-stride global array; `TimedEffectAndCueUpdate` consumes those flags and delegates slot rendering; the renderer draws a rectangular grid overlay and blits the slot's resource list. The checked-in decompile in [`LEGORR.full.c`](../decompiles/full/LEGORR.full.c) supports the address-level behavior below. The names of several flags and global fields remain provisional. Finding 240 already documents the renderer's caller relationship and the initialized geometry globals; this finding maps the setters and resource helpers into that flow.

## Request state and update cycle

Each timed-effect record has stride `0x27c`. `TimedEffectCueRequestSet @ 0x0046b700` writes the supplied cue value at `DAT_0054c274 + index*0x27c` and sets bits `0x1|0x2` in the record flags at `+0x278`. `TimedEffectPersistenceSet @ 0x0046b730` sets or clears bit `0x10`; `TimedEffectUpdateRequestSet @ 0x0046b770` sets bit `0x4`; and `TimedEffectTimestampReset @ 0x0046b7a0` copies the current global tick/time value `_DAT_0054bf3c` into the indexed record's time field. These are setters only. Representative callers include `SimulationPointerActionDispatch @ 0x0041baa0`, `TerrainPointerCommandUpdate @ 0x00425d90`, `EntityCommandStatusFeedbackDispatch @ 0x00428020`, `TerrainCommandFeedbackDispatch @ 0x00428330`, and `SimCategoryCellHitTest @ 0x0045b310`, which request cues or updates from pointer, command, and category interaction paths. The higher-level meaning of each cue kind is not fully established.

`TimedEffectAndCueUpdate @ 0x0046b7c0` iterates the fixed slot array. It ignores slots without either low request bit set. A slot lacking the update bit, or encountered after the per-pass update has already happened, has its timestamp field cleared. Otherwise the first slot whose timestamp is earlier than the global time (or follows a prior update in this pass) sets the shared `DAT_004aa64c` state and advances its timestamp by `delta`. For a slot with an attached object and the shared cue gate enabled, and when global state bit `0x100000` is clear, it calls `FUN_00464ef0` to update the gate. It renders at most one slot through `TimedEffectSlotRender @ 0x0046bc30`: if the first eligible slot is overdue, the timestamp advances without rendering, and subsequent requested slots have their timestamps cleared for this pass. Otherwise it renders that slot, marks the pass as updated, advances the timestamp by `delta`, and clears the update-request bit. Finding 225 identifies this routine as part of the timed effect/cue update path; Finding 240 records `TimedEffectSlotRender` as called from here.

## Overlay geometry and slot rendering

`RectangularGridOverlayGeometryDraw @ 0x0046b8b0` does nothing when the configured grid count `DAT_0054bf28` is zero. Otherwise it builds four nested rectangle coordinate lists from the supplied origin, extent, and count, then draws one central primitive and two rectangle batches using the supplied colors/parameters. The final parameter selects one of two central draw modes (`0` or `2`). Tooltip/grid setup initializes the geometry globals at `0x0046b1d0` (Finding 240); broader visual labels are not inferred from this helper alone.

`TimedEffectSlotRender @ 0x0046bc30` snapshots the grid rendering globals, computes the slot's screen origin and extent either from cell/grid fields or from its attached object, clamps the rectangle against configured viewport bounds, and invokes the geometry draw helper. For ordinary list-backed slots it walks the resource pointers beginning at record `+0x20c`, draws each populated resource at a running offset, and measures the maximum dimensions to advance the next row. For the object-backed path (record bit `0x8` set), it directly draws the resource at `+0x270`. The exact feature identity of the two branches is not proved; the field/control-flow distinction is direct.

## Resource helpers and callers

`RenderResourceBindingInitialize @ 0x0046c030` clears four output fields, resolves a resource using three candidate descriptors in order, stores the first successful handle in the second field, and records the supplied owner/value in the first field. `CopyFourFieldsAndConvertSecond @ 0x0046c0b0` copies four words then replaces the second with the result of `FUN_00473690`. `RecordResourceRelease @ 0x0046c0f0` releases the handle stored at record offset `+4` through `FUN_00472a40`. `AnimationResourceAdvanceTime @ 0x0046c110` forwards the handle at `+4` and the supplied delta to `FUN_00475120`; its return is always zero. `SceneObjectSetAnimationWithFallback @ 0x0046c130` tries the requested animation on the scene object at `+4`, then tries global default `DAT_004decc4` if the first call reports failure. These helpers are reused outside this cue path: `SceneEntitySlotTableRebuild @ 0x004083a0` and `FUN_0046c510` call `SceneObjectSetAnimationWithFallback`, and `EntityTeardown @ 0x00437540` calls `RecordResourceRelease`. The mechanics described here are therefore general resource operations, not behavior unique to timed effects.

## Limits and follow-up

The decompile establishes the slot stride, flag masks, request/update ordering, geometry construction, resource forwarding, and visible caller/callee edges. It does not establish the complete cue-kind enum, the user-facing meaning of persistence bit `0x10`, or why only one slot is rendered per update pass. Existing findings already cover the renderer, its initialization, and representative callers. A useful future slice would map cue-kind values to their simulation producers and displayed resources; static helper code does not provide that complete semantic mapping, so no duplicate implementation issue is created from this pass.
