# Finding 427 — Screen Effects and UI Text Paths

This map covers the 16 functions assigned by Issue #180. The routines form several adjacent paths rather than one subsystem: a timed screen-effect lane, formatted and scrolling text, menu layout/surface composition, and resource/configuration setup. The evidence below distinguishes observed calls and fields from likely meanings inferred from their use.

**Target and evidence.** Static analysis of the shipped `reference/LegoRR.exe`; function bodies are in [`LEGORR.full.c`](../decompiles/full/LEGORR.full.c). Address-level exports are available in [`legorr-screen-space-effect-lane.bundle`](../evidence/legorr-screen-space-effect-lane.bundle), [`legorr-frontend.bundle`](../evidence/legorr-frontend.bundle), and the engine-helper expansion bundles cited below. Existing findings [232](232-formatted-text-rendering-and-font-helpers.md), [258](258-interface-method-wrappers-overlay-refresh-and-deferred-set-relays.md), [370](370-screen-effects-surface-and-ui-helpers.md), [373](373-cursor-simulation-renderer-and-file-helpers.md), and [377](377-callback-registry-and-runtime-helpers.md) document neighboring wrappers and call paths.

## Timed screen-effect lane

`ScreenEffectLaneDispatch` (`0x0040aa10`) walks a fixed sequence of 0x20-byte records rooted at `DAT_004b8a84`. For records whose flag word at `+0x1c` has bit 0 set, it calls `ScreenEffectOpacityUpdate` (`0x0040aa40`) with the elapsed-time argument. The update reads the record's duration-like value at `+0x18`, opacity-like value at `+0x14`, item count at `+8`, and resource handle at `+4`. While elapsed time is below 15, it subtracts the delta from `+0x14`, calls `FUN_00483420(handle, index, 1.0 - elapsed/15, 4)` for each item, and advances elapsed time. At or beyond 15 it clears the active bit and releases the handle at `+0`.

The field roles “opacity-like” and “duration-like” describe their observed arithmetic; the record type and all field meanings are not named in the decompile. `ScreenEffectFlagsClearAndRelease` (`0x0040a3d0`) performs shutdown cleanup over the same 0x20-byte stride, beginning at the flags field address `DAT_004b8aa0`: for each active record it clears bit 0 and releases the handle seven words before the flags pointer. Its observed caller is shutdown handling in `PendingLevelName` (`0x0042f0c0`).

`ScreenEffectRecordSet` (`0x00435ebb`) directly writes three fields at offsets `+4`, `+8`, and `+0xc`, passes its fifth argument to `CameraSetTilt` (`0x00436860`), then directly writes its sixth argument at `+0x10`. `CameraSetTilt` conditionally stores the fifth argument at `+0x78` subject to flags and bounds at `+0xb8`, `+0x7c`, and `+0x80`, then updates render transforms. The setter is called from `GlobalRenderRecordSetFromInput` (`0x00425d50`), `TerrainPointerCommandUpdate` (`0x00425d90`), `OListEntityRecordParse` (`0x0042e020`), and `PendingLevelName` (`0x0042f0c0`). Despite the assigned alias `ScreenEffectRecordSet`, the observed tilt and transform effects suggest this record also carries camera/render state. The available evidence does not establish that it is the lane record consumed by `ScreenEffectLaneDispatch`; those structures should not be conflated based only on the shared naming.

A separate gate exists in `ScreenSpaceEffectDispatchIfEnabled` (`0x0040e8d0`). It checks bit 0 of `DAT_004c7ea8`, bit 1 of `DAT_0050034c`, and a nonzero handle in `DAT_004c7ea4` before calling `FUN_004248b0(handle, param1, 0, 1.0, 0)`. This is a gated dispatch path; the callee's semantic effect is covered in [finding 373](373-cursor-simulation-renderer-and-file-helpers.md).

## Formatted and scrolling text

`FormattedTextPrintfWidth` (`0x00401c50`) and `FormattedTextPrintf` (`0x00401c80`) are wrappers around `FUN_0047a150`. The width wrapper forwards a format string and varargs address and returns the helper's result; the other wrapper forwards its distinct argument set and varargs. Finding [232](232-formatted-text-rendering-and-font-helpers.md) describes the helper as the formatted-text rendering path and records its width result. `ScrollingTextDisplay` (`0x0040a0c0`) formats its input through a `%s_cconv` conversion, obtains text through helper routines, counts CRLF-delimited lines, copies them into a local line buffer, and repeatedly draws visible rows. It centers each row using the width wrapper and a draw helper, advances the scroll position after a time interval greater than `0x21` ms, and sleeps briefly when its required stream/text state is unavailable. Its observed direct caller is `MainMenuTextItem` (`0x004103d0`). The exact contract of its third parameter is not established by the current evidence.

`UiTextUnderscoresToSpaces` (`0x004102b0`) returns the original pointer for inputs longer than 255 bytes. Otherwise it copies into a reusable global buffer at `DAT_004db748`, replacing underscores with spaces, and returns that buffer. Observed callers include menu tick, save-menu layout loading, and menu construction. Because the short-input path returns shared storage, callers that need the converted value to persist must account for later calls overwriting it.

`TextLayoutOffsetForCentering` (`0x00411320`) uses zero vertical adjustment when its seventh argument is zero; otherwise it computes the negative half of its fifth argument, adds that to the third argument, then forwards to `FUN_004112e0`. `MenuMouseCoordinateUpdate` (`0x00411360`) calls it at three sites. The parameter names and coordinate-space contract remain unresolved.

`DebugPanelTextDrawUpdate` (`0x004230c0`) decrements a global blink timer by delta time; at or below zero it adds 12.5 and toggles `DAT_004de428`. When `DAT_00556fa0` is non-null, it measures and draws the pointed-to text using the formatted-text width wrapper and a draw helper, positioning it with state and screen-width values. `MainSimStep` sets the pointer to the selected type-2 object's name during debug rename mode and stores its projected coordinates at `DAT_00556fa4` and `DAT_00556fa8`; `EnginePreTick` edits the pointed-to string from typed keys and clears the pointer when editing is cancelled. The full pseudocode places this display update in the engine tick/render work, though the dedicated caller export examined for this function reported no callers; this caller discrepancy remains open.

Evidence: `ScrollingTextDisplay` [`ev_f78e4c1c2743b5596d53be5716f9584c4ac1237c2e5fe6c8c8c9592ed1f3b31e`](../evidence/legorr-frontend.bundle); formatted-text caller exports [`ev_c97ee291f504e48b7ffd54172de11b75ac102b536e6353fe79fa5e62672e2ddd`](../evidence/legorr-engine-helpers-expansion-7.bundle) and [`ev_63ba4fde944ce1812c47015477d8a2423e57b9e64bcca4d46ba88061f1d48a73`](../evidence/legorr-engine-helpers-expansion-7.bundle); underscore conversion body [`ev_259bd804d24a294fbdf1af85667dcaefd555930f5d7ab8e1fb81af25c1867985`](../evidence/legorr-engine-helpers-expansion-5.bundle) and callers [`ev_cb363e44689f1618607c1fa13c4ea2f336630dec958e2baa3694459a1984e2cb`](../evidence/legorr-engine-helpers-expansion-5.bundle); debug-panel body [`ev_1b40e83eb68ff421f03606dba0a11cbea8d693f23c76ab9a517f109b086bc722`](../evidence/legorr-engine-helper-audit-low.bundle).

## UI composition and resource setup

`PercentSplitSurfaceBlit` (`0x00411f10`) computes an integer percentage as `param4 * 100 / param5`, then uses it to divide a rectangle between surfaces stored at record offsets `+0x1c` and `+0x18`. It may also render segments referenced at `+0x20` and `+0x24` and conditionally draw pointer-selected blocks after a menu-pointer hit test. `MenuTick` (`0x00412c00`) is its observed caller. The input units and whether the percentage represents completion, capacity, or another measure are not identified by the callee alone.

`OverlayTextBufferRefresh` (`0x00418a00`) performs frame-side housekeeping before composing overlay entries: it rearms a handler, checks bits 1 and 2 in `DAT_004dc650`, checks `SystemStateFlags` bit `0x800`, and can call `TransitionControl(0,1)`. The engine tick reaches it before drawing (see [finding 258](258-interface-method-wrappers-overlay-refresh-and-deferred-set-relays.md)). This routine's global buffer layout is not decoded here.

`BubbleConfigTextureLoad` (`0x00407240`) reads the `Bubbles` child list from configuration. For entries with a leading `!`, it strips the prefix unless global bit `0x02000000` suppresses that entry; remaining names are mapped to slots, loaded as resources, stored in `DAT_00557864`, and initialized when non-null. `GameConfigInit` (`0x0041fb50`) calls it. `InterfaceMessageTabInfoTextLoad` (`0x00419430`) loads a text resource from its argument, stores the handle in `DAT_004dcd40`, and retains it; `GameConfigInit` calls it with `Interface_MessageTabs_infoOverFl`.

`SurfaceTextCharacterMapInitialize` (`0x0042b850`) builds character mapping/remapping tables and then invokes a surface-text/font helper. `TextureSetConfigLoad` (`0x0042bb60`) calls it. The observed table construction supports describing it as character-map initialization; the exact source atlas format and downstream rendering semantics need further tracing.

## Follow-up questions

- Identify the full record layouts and ownership rules for the active screen-effect lane and for records written by `ScreenEffectRecordSet`; prove or disprove any relationship between them.
- Trace the text-stream parameter and termination conditions in `ScrollingTextDisplay`, including the audio/stream helpers used along its wait path.
- Resolve coordinate and percentage units for `TextLayoutOffsetForCentering` and `PercentSplitSurfaceBlit` from their callers.
- Decode the overlay text buffer record layout and reconcile the debug-panel caller inventory with engine tick pseudocode.
- Trace the character-map table into the surface text renderer to identify its source configuration and atlas format.

These are research questions; the investigation did not establish a concrete behavior slice ready for implementation, so no implementation follow-up issue was created.
