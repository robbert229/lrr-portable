# Finding 188 — COM Video Route Has No Explicit `CoUninitialize` Call

The configured-video object constructor `FUN_00472390` calls `CoInitialize(NULL)` each time it creates a media object. Its cleanup path `FUN_00472430` releases the stored COM interfaces and frees its path buffer, but does not call `CoUninitialize`. The executable imports `CoInitialize` and `CoCreateInstance` but has no `CoUninitialize` import or visible call. Microsoft documents that each successful `CoInitialize` call, including one returning `S_FALSE`, must be balanced by a `CoUninitialize` call on that thread. The binary therefore has no explicit balancing call for this route. The HRESULT from `CoInitialize` is not checked, and this static finding does not establish runtime resource impact or exclude an unobserved indirect teardown mechanism.

**Evidence.** Shipped `reference/LegoRR.exe`, SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`. `FUN_00472390` at `0x472390` calls `CoInitialize`; `FUN_00472430` at `0x472430` releases seven stored interface pointers and a heap buffer, with no uninitialization call. `FUN_004726f0` at `0x4726f0` invokes that cleanup path. `objdump -p reference/LegoRR.exe` lists `CoInitialize` and `CoCreateInstance`, but no `CoUninitialize`; the decompilation contains no `CoUninitialize` call. Microsoft's [`CoUninitialize` documentation](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-couninitialize) specifies the balancing requirement.
