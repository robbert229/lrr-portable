# Finding 478 — Selection Groups and Selection State

This finding covers the 19 procedures assigned in [issue #132](https://github.com/robbert229/lrr-portable/issues/132). Evidence is the checked-in pseudocode in [`LEGORR.full.c`](../decompiles/full/LEGORR.full.c) and its callers. Function labels are descriptive; flags and numeric codes are reported as observed. Related context: [Finding 468](468-command-queue-and-selection-state.md) maps the selected-entity array, operation queue, and command dispatch; [PR #353](https://github.com/robbert229/lrr-portable/pull/353) contains a concurrent finding on related entity activity state.

## Selection-group records and cleanup

`ReleaseSelectionGroupResources @ 0x00409110` resolves a group record with `FUN_004090c0`; if one exists, it invokes a group cleanup helper, applies `FUN_00409a40` to the record's tracked entities, then unlinks/frees the group record through `FUN_004099f0`. No direct call site for this wrapper appears in the checked-in corpus. `ClearSelectionGroup @ 0x00409150` resolves the group, clears its selected-group state through `FUN_00432560`, walks the entity pointers counted at group `+0xcc` from `+0x2c`, clears bit `0x100` in each entity's word at `+0x3ec`, and calls `FUN_00402720(entity,0)`. It then performs group cleanup, clears a related pointer through `FUN_00403700`, and unlinks/frees the record. `UiActionDispatch @ 0x0041dca0`, case `0x10`, calls `ClearSelectionGroup` when the current cell record has bit `0x40000000`; otherwise that case takes a different helper path. These paths are distinct: one applies the per-entity `FUN_00409a40` updates, while the other clears the group-membership bit and calls the per-entity helper directly.

`ReleaseAllGroupRecords @ 0x004099d0` walks the global linked list rooted at `DAT_004b8a24` and releases each record with `FUN_004099f0`. That callee unlinks the target from the singly linked list using the link at `+0x24`, then frees the resource at `+0x14` and the record itself. A level teardown path calls both `SelectionStateFlagClearBit0` and `ReleaseAllGroupRecords`, establishing a teardown route in addition to clearing one group.

These accessors touch different globals and tables. Similar “selection” labels do not establish that `DAT_004dc650`, `DAT_004dcd48`, the indexed `DAT_004dc708` records, and the current-context pointer share a single flag/state model.

## Selected-entity consumers and drawing

`SelectedEntitiesAnyMatch @ 0x0041f420` retrieves the selected pointer array and count, calls a supplied predicate for each entity with the second argument, and returns 1 at the first match; an empty selection returns 0. `SelectedEntityDetachCallback @ 0x0041f6c0` is used as one such callback (the simulation dispatcher invokes it for cases `0x16` and `0x17`): it checks entity flags and either calls `FUN_00439e70(entity,0)` or passes the record at `+0x308` to `FUN_0043fc20`. Its callback return is always zero, so it performs cleanup rather than signaling a match.

`SelectionEntityCodeResolve @ 0x0041b9c0` consults the first selected entity and global configuration bits; it either returns the supplied value unchanged or writes and returns code `0x22`/`0x23` according to bit `0x80000000` at selected entity `+0x3e8`. `CatalogCallbackByIdDispatch @ 0x0041b680` calls it for catalog entries whose stored code is `0x22` or `0x23`, then passes the resolved value to its callback. `IndexedEntityValueGet @ 0x0041cab0` chooses among three indexed global arrays according to `FUN_0041c8f0` and `FUN_0041ca60`; `AdvisorAnimationPositionAndRequestUpdate @ 0x0041c4f0` uses it when its requested catalog type matches the current animation update. `SelectedEntitiesAnyPredicateMatch @ 0x00431a30` iterates the active selection from `FUN_00452580` and returns 1 when `FUN_00432770` accepts any entity and the supplied three arguments. `MainSimInteractionAndCellUpdate @ 0x00426520` calls it with different predicates and mode values in selection-aware interaction/placement branches; the returned boolean gates those branches, while their higher-level intent depends on the switch case.

`SelectedObjectOutlinesDraw @ 0x00424830` walks the current selected array and calls `SelectedEntityGroundMarkerRender` for each item, passing different color/intensity values for the first item and subsequent items. `SelectedEntityGroundMarkerRender @ 0x004248b0` skips entities rejected by `FUN_00449ff0`, projects the entity's world location through the supplied view, clips against screen dimensions, derives an eight-point ground outline from the entity bounds, and sends those points to `FUN_00485ff0` for drawing. A global mode scales the supplied color/intensity values by `0.3`; this is a visible render-mode effect, not evidence of a distinct selection set.

`SelectionRecordPointGet @ 0x00436ae9` reads a point from scene object slot 0 only when the supplied record's kind field is `1`; other kinds leave the caller's output untouched. `TerrainPointerCommandUpdate @ 0x00425d90` calls it to obtain the point used in its terrain-pointer update, and can write an adjusted point back through the paired setter.

## State flow and limits

Observed flow: group clear/release resolves a group record, updates or releases its member entities, then unlinks the record; selection consumers separately obtain the active entity array and apply either a supplied predicate or a render operation. `SaveMenuOpenFromReward @ 0x00462030` reads the current selection context and may call the setter with zero while entering its save-menu path. `SelectedEntityDetachCallback` is directly connected to the selection operation dispatcher, and `SelectedObjectOutlinesDraw` directly fans out to the ground-marker renderer. `ContextSelectedGlobalPointerGet` has no direct call site in this corpus; its broader use remains unresolved. Selection context/handle helpers expose additional global UI state, but this set does not establish a single owner that synchronizes those globals with group membership. `SelectionFlag10SetClear` has no direct call site in this corpus; indirect/callback use remains unresolved.

Focused follow-ups: identify every creator and owner of records rooted at `DAT_004b8a24`; trace writers of the selection-context and indexed flag tables; map `FUN_004090c0`'s group lookup key and the roles of group offsets `+0x2c/+0xcc`; and determine which UI mode selects between the two globals returned by `ContextSelectedGlobalPointerGet`.
