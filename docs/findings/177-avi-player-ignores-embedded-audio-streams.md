# Finding 177 — AVI Player Opens Video Streams but Not Embedded Audio

The AVI constructor calls `AVIStreamOpenFromFileA` once with stream type `vids` and stream index zero, then opens a frame retriever for that stream. It does not open an `auds` stream. The executable imports `AVIStreamOpenFromFileA` but has no second callsite or other AVIFIL32 audio-stream API in this playback module.

The reference installation has 17 AVI files under `reference/Data/AVI`. RIFF stream-header inspection finds one `vids` stream in each file and one `auds` stream in 16 of them: `intro.avi`, `landslid.avi`, `lavacha1.avi`, `lavacha2.avi`, `lavajug1.avi`, `lavajug2.avi`, `lmi640.avi`, `mbats.avi`, `outro1.avi`, `outro2.avi`, `rock1.avi`, `rock2.avi`, `slugs1.avi`, `slugs2.avi`, `slugs3.avi`, and `waterfal.avi`. `loop.avi` contains only `vids`.

This establishes that the AVIFIL32 movie path selects video and does not consume the embedded audio streams present in those assets. It does not rule out unrelated game sound effects or CD audio playing during a movie. This finding is scoped to that AVIFIL32 path: the separate DirectShow boot/level route adds both primary video and primary audio streams (finding 189), though that does not prove a specific file has audio or that it is audible at runtime.

**Evidence.** Shipped `reference/LegoRR.exe`, SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`; `FUN_0047e800` at `0x47e800` passes `0x73646976` (`vids`) and stream index zero to its only `AVIStreamOpenFromFileA` call. The function and thunk are in `docs/decompiles/full/LEGORR.full.c`; the import table contains no other AVI audio API. The 17 AVI files are in `reference/Data/AVI`; their `LIST strl`/`strh` stream types were read from the RIFF headers. Microsoft's [`AVIStreamOpenFromFile` documentation](https://learn.microsoft.com/en-us/previous-versions/ms706774%28v%3Dvs.85%29) confirms that the four-character `fccType` selects one stream from the file.
