# Finding 207 — Configured Video Releases Its Stream Without an Explicit Stop Call

The configured-video setup starts the multimedia stream with `SetState(STREAMSTATE_RUN)`. Its normal completion, skip, and error paths then release the wrapper's COM interfaces; the playback helpers do not issue a matching `SetState(STREAMSTATE_STOP)`. The static trace identifies interface release as the game's visible cleanup action. It does not establish whether DirectShow stops the graph immediately when those references are released or what internal teardown the implementation performs.

**Evidence.** In shipped `reference/LegoRR.exe` (SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`), `FUN_004721e0` (`0x4721e0`) calls the stored `IMultiMediaStream` interface's vtable slot `+0x1c` with state value `1` after sample setup; this is `SetState(STREAMSTATE_RUN)`. The normal boot/level wrapper `FUN_00415910`/`FUN_00415990` calls `FUN_004726f0` after playback, and `FUN_004726f0` invokes `FUN_00472430` to release the wrapper interfaces. The level route `FUN_0042efc0` likewise calls `FUN_004726f0` after its update loop. Neither those loops nor `FUN_00472430` call `SetState` with state `0`; the destructor releases interfaces and frees the wrapper. Microsoft's [DirectShow video-streaming sample](https://learn.microsoft.com/en-us/windows/win32/directshow/video-streaming-sample-code) explicitly calls `SetState(STREAMSTATE_STOP)` after its `IStreamSample::Update` loop, providing a reference sequence for the call not observed in this binary.

This is a static call-path comparison, not evidence of a running graph after cleanup or a runtime leak.
