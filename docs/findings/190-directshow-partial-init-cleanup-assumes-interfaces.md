# Finding 190 — DirectShow Partial-Setup Cleanup Assumes Every Interface Exists

The `AMMultiMediaStream` wrapper zeroes its interface fields before setup. `FUN_004721e0` then acquires the primary video stream and several related DirectDraw interfaces in sequence. If any acquisition fails, its cleanup block unconditionally dispatches `Release` through the fields at object offsets `+0x08`, `+0x0c`, `+0x18`, and `+0x10`, without checking them for null. A failure before a later field is populated leaves that field zero, so the cleanup path can make an indirect call through a null pointer. The caller `FUN_00472390` ignores the helper's Boolean result. It also does not clear fields after the helper releases any successfully acquired interfaces, so a later destructor can attempt to release those same pointers again if the partially initialized object is retained and destroyed.

This is a conditional failure-path hazard derived from static control flow; no COM failure was induced at runtime.

**Evidence.** Shipped `reference/LegoRR.exe`, SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`. `FUN_00472390` at `0x472390` zeroes object fields `[2]` through `[6]` before calling `FUN_004721e0`. The helper at `0x4721e0` populates those fields through successive COM calls, then on any negative HRESULT enters a cleanup block that calls each field's vtable slot `+8` (Release) without null guards or clearing the fields. `FUN_00472430` at `0x472430` later conditionally releases the same fields. All three functions are in `docs/decompiles/full/LEGORR.full.c`.
