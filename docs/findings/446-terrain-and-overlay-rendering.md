### State and data flow

The terrain mesh path starts when `TerrainCellQuadGeometryEmit` consumes a cell dirty flag and emits the cell quad. It raises a second dirty bit, which `TerrainDirtyCellQuadNormalEmitPass` later scans; that pass obtains normalized corner normals through `TerrainCellSurfaceNormalGet`, rewrites vertices, and clears the bit. `SceneQuadGridEmit` is a separate initialization path that builds a fixed grid of quad faces and finalizes a render record.

Overlay visibility has two observable layers: `GraphicsOverlayVisibilitySet` updates a global only on change and propagates it to a renderer, while `IndexedSurfaceEntryHideAndRecord`/`IndexedSurfaceEntriesRestore` hide indexed resources temporarily and restore precisely the recorded entries. `IndexedSurfaceResourceAllocate` supplies the indexed surface/table backing this path. The reward/info-panel and scroll constructors build separate text/rectangle records consumed by their panel callers. Placement preview combines rotated footprint coordinates, emitted scene geometry, and terrain span validation.

The described calls, branches, record offsets, and flag writes are direct pseudocode observations. Terms such as “overlay,” “track,” and “footprint preview” follow named routines/callers; unknown field and flag semantics are not inferred beyond those paths.

- Resolve the two cursor-slot structures and mode values used by `SimTrackCursorHitTest`.
- Validate scene-grid face orientation and placement preview span thresholds against captured runtime geometry.
- Decode the panel record fields and surface-visibility wrapper through their consumers before assigning domain names to numeric fields.
