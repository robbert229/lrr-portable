## Control and target flow

The startup path loads the camera speed, drop-off, acceleration, and mouse-scroll indent values before calling `CameraViewContextSet`. It then loads `MinDist`, `MaxDist`, `MinTilt`, and `MaxTilt` and applies the corresponding bounds to the primary camera context. The setters store distinct limits and values in the context record; the override flag at bit 3 bypasses each bound check. The camera transforms are updated for the `+0x78` and `+0x84` values, while the distance setter stores its value for later context/render use.

`MainSimStep` applies keyboard deltas to the primary camera context through `CameraPanAxisUpdate`, `CameraTiltAxisUpdate`, and `CameraZoomUpdate`. Separately, `ViewContextTick` advances the context's follow/free state and its scene nodes. The function names are useful labels, but the bodies show that `CameraPanAxisUpdate` increments the field passed to `CameraSetTilt`, while `CameraTiltAxisUpdate` increments the separate `+0x84` value; the physical axis convention for the latter remains uncertain.

For pointer routing, `CameraPointerRayRoute` projects a screen coordinate at two depths using the current camera interface and passes the resulting direction to the line/plane intersection helper. Its caller `CursorRayToCameraRoute` uses the returned point to derive a camera-relative adjustment. `ViewportTargetPositionClamp` is a separate target-state path: it accepts either a cell pair or an entity, clamps against terrain dimensions with the configured inset, stores one of two global target positions, and sets a dirty flag. The available static trace does not establish that every pointer-ray result flows through that target clamp.

## Focused follow-up

- Confirm the coordinate/rotation semantics and units for the values at camera offsets `+0x78` and `+0x84`, including whether the axis-oriented helper names match the scene transforms.
- Trace all callers that consume the two viewport target slots and determine what the dirty bit triggers.
- Verify whether the line/plane intersection caller constrains negative intersection parameters; the shared intersection helper does not reject them itself (Finding [388](388-geometry-and-matrix-primitives.md)).
- Trace when each of the three view-context modes is entered and whether the three contexts share any scene-node handles.
