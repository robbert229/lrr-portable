# Finding 455 — Terrain Command Feedback and Cell Interaction

This finding follows the eight procedures assigned by issue #154 across terrain-cell command creation, descriptor presence checks, pointer-driven feedback, special-state predicates, and a palette-resource lookup. The pseudocode directly establishes the branches, offsets, flags, and callees below. Names such as “feedback” and “palette” reflect surrounding call paths; numeric cell and input flags remain uninterpreted.

| Address | Procedure | Observed behavior |
| --- | --- | --- |
| `00402510` | `TerrainCellCommandCreate` | Proceeds only when `FUN_00432ec0` and `FUN_00432f00` both return zero and `FUN_00432f90(x,y)` returns nonzero. It then allocates command kind 8, stores the coordinate pair, applies command flags based on the two boolean arguments, initializes and links the record, sets bit `0x80` (and optionally `0x20000`) in the command flags, and, when control argument `param_2` is zero, refreshes the cell resource and sets cell flag `0x800000`. |
| `004090a0` | `TerrainCellPredicateCheck` | Returns whether `TerrainDescriptorFindExact` finds a descriptor for the supplied key. |
| `0040d3f0` | `TerrainCellSpecialStatePredicate` | Calls `FUN_00432aa0(x,y,1)`; if it succeeds, returns true immediately when the last argument is zero, otherwise returns the result of `FUN_00432170` on the coordinate pair. Its flag/state meaning is unresolved. |
| `00425d90` | `TerrainPointerCommandUpdate` | Runs only when global input-state bits `0x2` and `0x1000` are set and bit `0x100` is clear. It accumulates pointer movement, updates the terrain cursor after a distance threshold, and dispatches `TerrainCommandFeedbackDispatch` when the pointer remains on an eligible cell; it also handles map-edge clamping and several cursor/status transitions. |
| `00428330` | `TerrainCommandFeedbackDispatch` | Suppresses duplicate work when the pointer coordinate changes, then examines the target cell flags and byte fields. It builds a localized feedback string using cell/object data or chooses a message key from numeric flag conditions, and sends it through the message set/update/dispatch helpers. |
| `00428780` | `TerrainCellCommandPredicate` | Returns true when the global mode permits the cell, or when a global bit test passes and the selected cell’s byte at `+4` is zero; otherwise returns false. The tested global bits are kept numeric. |
| `00429160` | `TerrainCellPaletteResourceAtGridPosition` | Computes the row-major cell index, combines the cell byte at `+1` with `index * 9`, and passes that value and the level’s resource table at `+0x7c` to `FUN_0040b850`. The encoded selector’s meaning is not established. |
| `00432550` | `AlwaysAcceptPlaceCommandCell` | Returns `1` unconditionally. Its caller uses it as the cell-eligibility callback for command kind `0x16`. |

## Interaction paths

`UiActionDispatch` uses `TerrainCellPredicateCheck` to gate actions 5 and 7 against an existing descriptor. Action 5 also checks the terrain-coordinate helper before continuing; action 7 checks a cell byte before entering the shared descriptor path. For action 6 it checks the coordinate helper and sets up the selected-cell action. Action `0x10` calls `TerrainDescriptorTilesResetAndFree` or `ClearSelectionGroup` depending on cell flag `0x40000000`. In the cases that construct a cell command, `TerrainCellCommandCreate` allocates command kind 8, applies its flags, and may refresh the cell and set flag `0x800000`.

`MainSimInteractionAndCellUpdate` handles pointer interactions and calls `TerrainCommandFeedbackDispatch` on relevant cursor paths. `TerrainPointerCommandUpdate` is the drag/pointer-state path: it gates on input bits, measures movement from the saved pointer position, clamps coordinates against map bounds, and can ask the feedback dispatcher to update the hovered cell. Both helpers use cached coordinates to avoid repeating work for the same cell. `TerrainCommandFeedbackDispatch` then branches on the cell’s `+8` flags, `+0xc` byte, and attached record at `+0x10`; message keys and localized strings are selected from these values. The precise gameplay meaning of those bits remains unresolved.

`TerrainCellSpecialStatePredicate` is used by the terrain-neighbor and cell-corner scans, as well as activation and terrain-interaction helpers. In those callers it is combined with bounds checks, cell flags, object/type bytes, and the separate marker grid at `DAT_004c7df8`; no single universal “placeable” interpretation follows from the helper alone. `TerrainCellCommandPredicate` is consulted repeatedly by `MainSimInteractionAndCellUpdate` and by `BuildingPlacementFootprintRenderAndValidate`, so it supplies a shared mode/cell-byte test in both interaction routes.

The placement eligibility path `PlaceCommandEligibilityCheck` calls `AlwaysAcceptPlaceCommandCell` after it has identified command kind `0x16` and verified the command record’s object type. `FUN_00409550` also calls it on `param_1 + 0xc`; when accepted, it emits kind-6/7 descriptor commands using family-`0xf` values, then sets bit `0x4` in the owning record’s `+0xd0` state word. The callback itself imposes no terrain restriction; any restrictions in these paths come from their callers and surrounding command tests. `TerrainCellPaletteResourceAtGridPosition` is called by `EntityConditionalTypeFiveSpawn` after creating a linked type-five entity, then supplies a resource handle to the entity’s resource setter. Finding 13 maps the tile-variant filename and resource-loading path; Finding 223 discusses border cell checks used elsewhere in placement and initialization.

## Follow-up questions

- Identify the meaning of the cell flags and pointer-mode bits that select feedback message keys, using runtime or config-backed evidence.
- Determine the coordinate and special-state contracts of `FUN_00432aa0` and `FUN_00432170`, and whether the special predicate is intended to model one terrain condition or several.
- Resolve the encoded value passed by `TerrainCellPaletteResourceAtGridPosition` into `FUN_0040b850`, including the purpose of the `index * 9` component.
- Trace how command kind 8’s `+0x5c` bits are consumed after `TerrainCellCommandCreate` links the record.
