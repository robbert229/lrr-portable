# Finding 189 — Configured Videos Add Primary Video and Audio Streams

The configured-video DirectShow path initializes an `AMMultiMediaStream`, then adds two media streams before opening the file. The first uses the primary-video purpose ID with the game's DirectDraw object and flags zero. The second uses the primary-audio purpose ID with a null source object and flags `1`. Microsoft's DirectShow API defines that flag as `AMMSF_ADDDEFAULTRENDERER`, which requests the default renderer for the audio stream. The configured boot/level route therefore sets up both video and audio playback.

This does not establish that any particular file contains an audio stream or that sound is audible on a given machine. The separate AVIFIL32 credits route opens only a `vids` stream (finding 177).

**Evidence.** In `reference/LegoRR.exe` (SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`), `FUN_004722b0` at `0x4722b0` calls the `IAMMultiMediaStream::AddMediaStream` vtable slot twice: it passes the DirectDraw object, purpose GUID at `0x49f288`, and flags `0` for the first call; then null object, purpose GUID at `0x49f298`, and flags `1` for the second. The GUID data and call order match `MSPID_PrimaryVideo` and `MSPID_PrimaryAudio`. Microsoft's [MSPID reference](https://learn.microsoft.com/en-us/windows/win32/directshow/mspid) defines those purposes; its [video streaming sample](https://learn.microsoft.com/en-us/windows/win32/directshow/video-streaming-sample-code) uses the same DirectDraw video stream and default-rendered audio stream calls. Finding 177 records the distinct AVIFIL32 stream selection.
