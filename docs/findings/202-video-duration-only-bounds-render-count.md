# Finding 202 — Video Duration Bounds the Render Count, Not Frame Timing

The configured-video helper does not use its duration query to delay or schedule frames. `FUN_00472530` calls `IMultiMediaStream::GetDuration`, divides the returned 100-nanosecond `STREAM_TIME` by 10,000, and returns the value in milliseconds. `FUN_00415700` increments a local counter by one for each rendered iteration and exits if that count exceeds the queried duration. The duration is therefore a loose upper bound on render iterations; it is not the frame clock. The update callback's synchronous sample update is the operation that can wait for a video sample.

The HRESULT from `GetDuration` is ignored. Microsoft documents that `GetDuration` returns `S_FALSE` and writes zero when the stream is live or its duration cannot be determined. In that case, after the first successful sample update and render, the counter is `1` and exceeds the zero duration, so the helper exits without another update attempt.

**Evidence.** Shipped `reference/LegoRR.exe`, SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`. `FUN_00472530` (`0x472530`) calls vtable offset `+0x24` on the stored multimedia-stream interface with an 8-byte output buffer, then calls signed 64-bit division by `10,000`. In `IMultiMediaStream`, `GetDuration` is the method at slot `9` (`+0x24`), after the three `IUnknown` entries and six earlier interface methods. `FUN_00415700` (`0x415700`) initializes a float counter to zero, increments it by `1.0` after each `FUN_00477f30` render, obtains the value from `FUN_004726c0` (`0x4726c0`), and exits when that value is less than the counter. Microsoft's [GetDuration reference](https://learn.microsoft.com/en-us/previous-versions/windows/embedded/ms931676%28v%3Dmsdn.10%29) defines the output as stream duration and says `S_FALSE` sets it to zero when duration is unavailable. Microsoft's [IStreamSample::Update reference](https://learn.microsoft.com/en-us/previous-versions/ms786825%28v%3Dvs.85%29) documents synchronous behavior when no async flag, event, or callback is supplied.

The zero-duration case is a statically derived edge case; the shipped configured AVI files are recorded media, and no runtime failure was induced.
