# Finding 429 — Advisor and Message UI State

This map covers the 16 functions assigned by Issue #175. They connect configured message labels and text/image slots to the advisor display worker, while also including tooltip state, a camera-route entry point, a selector-bit helper, and per-command sample statistics. Some of these are neighboring utilities rather than one subsystem; their observed data flow is described separately.

**Target and evidence.** Static analysis of shipped `reference/LegoRR.exe`; function bodies are in [`LEGORR.full.c`](../decompiles/full/LEGORR.full.c). ## Configured messages and display slots

`UiMessageStringsInit` (`0x0046a7f0`) installs the 26 built-in action/help strings in the global message-label block and stores two caller-provided text values and two numeric values; their exact roles are not fully established here. It also sets the selected-message sentinel to `0x1a` and uses a default duration of 100 when the supplied final value is zero. `GameConfigInit` calls it. `MessageLabelIndexFind` (`0x0046aad0`) compares a label case-insensitively against that table and returns its zero-based slot. `TextMessagesConfigLoad` (`0x00434af0`) uses the lookup to route each `TextMessages` entry to `TextSlotMessageAssign`; its `TextMessagesWithImages` entries go through `TextSlotMessageWithImageAssign` (finding 248).

`TextSlotMessageAssign` (`0x0046ab10`) frees the prior slot string, allocates a copy of the new text, converts `_` to spaces and the two-character sequence `\\n` to a line feed, then releases and clears any cached image surface for that slot. `TextSlotMessageWithImageAssign` (`0x0046abb0`) first performs that text assignment, parses an associated numeric layout value, loads the supplied image resource, and initializes it if loading succeeds. The text and image tables are indexed by the same slot, but the exact meaning of the parsed layout value is not established by the loader alone.

`TextLayoutGeometryStoreAndApply` (`0x0046a950`) stores a supplied rectangle, layout value and scale in shared globals, derives a lower coordinate by subtracting the font record's line-height field, and calls `AdvisorTextBoxRecordCommit` (`0x0046a9e0`). The commit helper converts the stored positions through float-to-integer operations, writes two float pairs into the text widget, copies the rectangle into shared geometry fields, and clears bit 0 of an associated state word. `GameConfigInit` invokes the layout helper for the `Interface_MessagePanel_MsgPanel` configuration entry. The names of the tuple fields beyond their use as geometry remain inferred.

`MessageOverlayStateInit` (`0x0046aa90`) commits the current geometry, restores the message-slot sentinel, clears message/request globals and the state word, and resets both configured text widgets with `TextBufferReset`. Observed callers include `PendingLevelName`, `TutorialNerpScriptFileLoad`, and `AdvisorDisplayStateResourcesRelease`; this establishes reset/teardown use, not that all three callers correspond to the same user-facing transition.

## Advisor request, animation, and presentation

`AdvisorTextRequestSetup` (`0x0046ac20`) stores a request value, substitutes `0x8000` for a zero mode, ORs in `0x10000`, asks `FUN_00456830` to prepare the request, and sets bit 0 in the advisor state word at `DAT_00503664`. `AdvisorScrollStepAdvance` (`0x00453920`) calls it. `AdvisorTextDisplayWorker` (`0x0046ad00`) handles both queued requests and the active configured message slot. For a pending request it resolves text through `FUN_00456830`, copies the resolved result into the primary text widget, and decrements the request countdown unless the `0x8000` marker is set. For a configured slot it checks global state gates, copies slot text into one of the two widgets with `ObjectiveAdvisorTextCopy`, updates a duration timer, calls the overlay draw/update helpers, draws wrapped text through `TextBufferDrawWrapped`, and blits the slot image when present. Findings 94 and 57 trace the parser/text-widget and incident-message producer paths; static calls do not establish that every request is visible at runtime.

`AdvisorTextAnimationUpdate` (`0x0046ac60`) selects the current slot and may seed a timer from the configured duration, asks `FUN_00464c70` for a related record, and calls `FUN_00464ef0` when the outer state gate permits. It sets or clears bit 2 in `DAT_00503664` according to whether the selected slot matches and the final input is nonzero. `MessageOverlayStateInit` clears the word; `AdvisorTextDisplayWorker` tests and clears bit 0. These uses establish the word as advisor/message overlay state, while the independent policy meanings of bits 0 and 2 remain unresolved. Its callers include the advisor transition worker, simulation interaction/update paths, objective tick, and entity-placement feedback; finding 40 shows one transition-worker call path.

## Tooltip text and geometry

`TooltipOverlayStateInitialize` (`0x0046b1d0`) publishes the built-in tooltip label pointers, stores the supplied cell/overlay geometry parameters, derives expanded and contracted margins by adding or subtracting 40% of selected dimensions, clamps those fractions to `[0,1]`, and clears the large overlay-state record block. `GameConfigInit` calls it. `CaseInsensitiveNameTableLookup` (`0x0046b4d0`) searches the tooltip label table case-insensitively and returns a one-based index. Config loaders use this index when resolving tooltip or panel-button names (findings 240 and 248).

`UiTextEntryLoad` (`0x0046b520`) formats a configured entry before initializing a slot. An `@` prefix strips the marker and loads the remainder as a resource, setting slot bit 3. Otherwise it converts `_` and escaped `\\n` into display characters, measures/draws the resulting string with `FormattedTextPrintf`, and clears bit 3. It then resets several per-slot counters and sets bits 0 and 1. Callers include help-button layout, interface-back-button setup, terrain-pointer feedback, region-containment UI, advisor-tooltip config, entity-command feedback, and terrain-command feedback. The exact meanings of those state bits are not established.

## Adjacent helpers in the assigned set

`CameraMoveCommandRoute` (`0x0046a730`) advances the linked-record chain through `FUN_0046a700` and, when `DAT_004aa450` is nonzero, enumerates entities through `FUN_004377b0` with callback `LAB_0046a5c0` (finding 389). The routine is distinct from the message display flow; the chain fields and callback effect remain unresolved. `FirstSetFlagOrdinal` (`0x0046a760`) returns the one-based index of the lowest set bit among bits 0–12, or zero when none are set. `SceneObjectStateDispatch` uses this ordinal to select the corresponding state path (finding 389).

`CommandSampleStatsAccumulate` (`0x0046b660`) updates a stride-`0x27c` per-kind statistics record: a null sample clears two running values; a non-null sample adjusts the rolling window, adds the sample value, updates a high-water mark, and stores the sample pointer at the current log index before incrementing that index. Its callers include `SimulationPointerActionDispatch` and `EntityCommandStatusFeedbackDispatch` (finding 254). The record's user-facing statistic names remain unknown.

## Unresolved questions and follow-up

- Identify the record fields and state-bit meanings used by advisor requests, current-slot timers, and the two text widgets.
- Trace how `TextMessagesWithImages` assigns its numeric layout value and confirm resource/image ownership across reassignment and reset.
- Establish the selection rule for the linked-record camera route and the effect of its entity callback.
- Identify the semantic labels and consumers for each command-stat sample field and the sample-log indexing behavior.

These are research questions; this pass did not establish a concrete behavior implementation slice, so no implementation follow-up issue was created.
