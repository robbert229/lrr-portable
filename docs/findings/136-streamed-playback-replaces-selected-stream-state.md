# Finding 136 — A New Stream Replaces the Selected Stream State

The stream route in `FUN_0047b970` selects one of two global stream-state records according to whether its second argument is zero or nonzero. If the selected record is marked active or still has a buffer handle, the helper calls `FUN_0047ba20` before loading the new stream. That cleanup clears the active marker, sends a stop call through buffer vtable slot `+0x48`, releases the parsed stream format/data, releases the buffer, and clears its handle.

After a successful load, `FUN_0047b970` sets the selected buffer's position through vtable slot `+0x34` with value zero, calls slot `+0x30` with arguments `(0, 0, 1)`, marks the selected stream state active, and returns success. A failed load clears the active marker and returns failure. Therefore, a successful new request replaces an existing stream in the same selector state; the two state records are independent in the helper.

`FUN_0047ad70` reaches this helper only for entries carrying bank flag `0x8`, which the loader sets for `@` streamed entries (findings 107 and 63). Its assembly passes the fourth argument of `FUN_0047ad70` as the stream-state selector. Finding 137 traces selector zero from level-name/tutorial-name handlers and selector one from a dynamic sound-instance path; whether that latter path uses a streamed alias remains unknown. The vtable calls are reported at their observed slots; no audible result was tested.
