# Finding 199 — DirectSound Keeps Its Default Distance Factor

The sound initializer queries the DirectSound 3D listener and later sets rolloff and Doppler factors, then commits those deferred settings. It does not call listener vtable slot `+0x2c` (`SetDistanceFactor`) or slot `+0x28` (`SetAllParameters`); the listener update path likewise makes no such call. The distance factor therefore remains DirectSound's default of 1.0 for this executable's observed setup.

DirectSound defines its distance factor as meters per vector unit. With the default factor of 1.0 and the scene-relative Direct3DRM vectors passed through unchanged (finding 196), DirectSound interprets each frame-space vector unit as one meter. Direct3DRM itself does not assign a physical unit to those coordinates, so this establishes the audio-system mapping, not the game's intended real-world scale.

**Evidence.** Static disassembly of shipped `reference/LegoRR.exe`, SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`: listener initialization at `FUN_0047a640` (`0x47a640`) calls listener slots `+0x3c` (rolloff), `+0x30` (Doppler), and `+0x44` (deferred commit). Listener call sites elsewhere use `+0x34`, `+0x38`, `+0x3c`, and `+0x44`; no call to `+0x2c` or `+0x28` was found. Microsoft documents that the [distance factor is meters per vector unit](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee418003%28v%3Dvs.85%29), and that its [default value is 1.0](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/ksproperty-directsound3dlistener-distancefactor).
