# Finding 163 — A Stored View Provider Feeds DirectSound Listener State

`FUN_0047ab80` stores a view-related object in `DAT_00506688` when sound is initialized. The level setup path and the two view-mode branches in `FUN_004295f0` call this setter with objects selected from the current level/view records. `FUN_0047aba0` checks that sound is active and a provider is stored, then calls `FUN_0047abc0`.

The helper calls the stored frame interface's vtable slot `+0x68`, then passes the returned object through slot `+0x60` and forwards the resulting three floats as listener position through listener slot `+0x38`. A separate call through frame slot `+0x7c` supplies two three-float vectors that are forwarded as listener orientation through slot `+0x34`. The listener call passes them in DirectSound `SetOrientation` order: front vector, then top vector. Each output vector is compared component by component to cached values using exact float `==`; a difference in position or either orientation vector triggers the corresponding setter. If any changed, the helper calls listener slot `+0x44` once to commit the deferred changes. The slot identities align with the `IDirectSound3DListener` interface, where finding 62 separately maps slot `+0x3c` to the rolloff setter.

This identifies the data source and the listener properties written by the helper. The frame-tick entry `LAB_004232e0` calls `FUN_0047aba0` once per tick, after other level-update calls. Finding 02 traces that label as the registered frame callback. Finding 196 resolves the provider calls: they obtain the provider frame's scene, then request position and orientation relative to that scene; the helper passes those vectors to DirectSound without coordinate conversion. The game-specific physical unit remains unknown because Direct3DRM positions are unitless.

**Evidence.** Static decompile and disassembly of shipped `reference/LegoRR.exe`, SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`: `FUN_0047ab80` at `0x47ab80` stores the provider; `FUN_0047aba0` at `0x47aba0` gates and dispatches the update; `FUN_0047abc0` at `0x47abc0` reads/caches vectors and calls the listener; `FUN_0047c0c0` at `0x47c0c0` performs the component-wise equality check. The frame-tick label `LAB_004232e0` calls `FUN_0047aba0` at `0x423670`; finding 02 traces `LAB_004232e0` as the engine's registered frame callback. Level setup at `FUN_0041fb50` and view-mode transitions at `FUN_004295f0` select providers. The listener interface acquisition is documented in finding 119; the rolloff setter and its clamp are documented in finding 62. Microsoft lists the [IDirectSound3DListener8 interface methods](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee418003%28v%3Dvs.85%29), including position, orientation, and deferred-settings commit; its [DS3DLISTENER structure](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee416817%28v%3Dvs.85%29) names the orientation fields `vOrientFront` and `vOrientTop`.
