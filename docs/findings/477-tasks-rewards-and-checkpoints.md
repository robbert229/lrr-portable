# Finding 477 — Tasks, Rewards, and Checkpoints

This finding follows the 46 procedures assigned in [issue #147](https://github.com/robbert229/lrr-portable/issues/147), focusing on task configuration, checkpoint progress, reward presentation, and the campaign/save handoff. The source evidence is the checked-in pseudocode in [`LEGORR.full.c`](../decompiles/full/LEGORR.full.c) and its callers. Numeric fields and flags are kept literal where their semantic labels are not established. [Finding 09](09-reward-task-manager.md) contains the broader task-record layout; [Finding 44](44-reward-buttons-use-separate-save-routes.md) corrects the two reward-button routes; [Finding 08](08-save-and-checkpoints.md) traces the save formats and persistence layer.

## Task table setup and resources

`TaskBlockInit @ 0x0045f030` allocates and zeroes a `0x318c`-byte block, sets ten task entries at stride `0x210`, assigns the names Crystals, Ore, Diggable, Constructions, Caverns, Figures, RockMonsters, Oxygen, Timer, and Score, then invokes each resource/config loader. `TaskSoundsLoad @ 0x0045f1f0` resolves a `Reward.Sounds.<task>` value into the record at `+0x208`. `TaskFontLoad @ 0x0045f230` resolves `Reward.Fonts.<task>`, creates a font handle when present, and otherwise stores the default font handle. `TaskBoxImages @ 0x0045f290` resolves a per-task box image (with the fallback path gated by a global flag), reads its file/coordinates, creates a surface, and sets the record's box-image flag on success. `TaskImages @ 0x0045f3e0` does the corresponding regular image load and sets its image flag. `TaskBoxRect @ 0x0045f530` loads the box rectangle, adjusts it through `FUN_00413f00`, stores its dimensions, and sets the associated record flags. `TaskFlicPath @ 0x0045f5f0` loads a per-task FLIC path and four rectangle values and sets the FLIC flag. These functions expose the config-to-task-record flow; details of the record layout are cross-referenced above rather than repeated here.

`TaskBlockFinish @ 0x0045f750` walks the ten records, flushing image and font resources only when the corresponding record bits are set, then frees the task block. `TaskFlushImages @ 0x0045f7b0` releases the surface handle at `+0x200`; `TaskFlushFont @ 0x0045f7d0` releases the font handle at `+0x204`.

## Reward configuration and checkpoint snapshot

`RewardInit @ 0x0045f7f0` stores the configuration handles, reads screen-level `Reward` settings (wallpaper, display/centering modes, scroll and vertical spacing, fonts, completion/failure/quit text, and text position), calls VC5 `atof` for both scroll fields (an absent value uses the shared empty-string fallback, which parses as zero), calls `FUN_0045faf0` for button resources, and returns success. `FUN_0045faf0 @ 0x0045faf0` loads SaveButton and AdvanceButton image/rectangle data and returns success only when both primary button surfaces exist.

`CheckpointBlobBuild @ 0x0045fda0` allocates and zeroes a `0x318c`-byte checkpoint blob. It reads reward enable/modifier/timer/display settings, copies ten `0x210`-byte task records from the live task block into the blob, and refreshes each copied task's importance and quota. For `Level03`, it additionally writes `1` at blob offset `0x868`. `TaskImportanceRefresh @ 0x004600a0` reads `Reward.Importance.<task>` into record `+0x24`, defaulting through the configuration parser when absent. `TaskQuotaRefresh @ 0x00460140` reads `Reward.Quota.<task>` into `+0x28`, with its fallback value also supplied through the parser.

`CheckpointBlobFree @ 0x004601e0` frees the current blob; `CheckpointBlobGet @ 0x004601f0` returns its global pointer. `SelectedLevelStartObjectUpdate @ 0x00460200` checks the active level state and invokes the blob getter using its `+0x10` field; the returned value is not stored by this procedure. `StartLevelSelected @ 0x00460220` requires an active level state and blob, builds the kind-4 entity index list, copies 102 dwords to `DAT_005529c4`, and resolves the `Pilot` operation into `DAT_00555118`. `EntityType4IndexListBuild @ 0x00460290` calls `FUN_004377b0` with `EntityType4IndexListAppend`, then scans 15-by-16 grid positions through `FUN_004374a0` and copies 102 dwords to its output. `EntityType4IndexListAppend @ 0x00460310` resolves an entity and, for kind 4, appends its index value from `FUN_004396c0` to the output list.

## Progress aggregation and task percentages

The runtime call chain is visible in `KeepRunning @ 0x00435940`: when the level-state gate passes, it calls `CheckpointBlobBuild`, `CheckpointBlobTaskProgressRefresh`, `RewardScreenTick`, then `CheckpointBlobFree`. This is direct ordering evidence for a temporary per-frame checkpoint/reward snapshot; it does not by itself establish when a save is committed.

`CheckpointBlobTaskProgressRefresh @ 0x00460360` requires a current level and blob. It copies eight global values when the global enable is set, resets aggregate fields, snapshots score/stat counters (including `DAT_00554adc`, `DAT_00554efc`, `DAT_00555324/28/2c`, `DAT_00555330`, `DAT_00555118`, and `DAT_00555120`), then scans the level's grid. For each cell it calls `FUN_0042c5b0`, increments the visited-cell count, accumulates two returned values, and increments additional counters according to the cell type and bits in the cell record. It then derives task totals and bounded percentage fields, clamps task values to `0..100`, invokes `CheckpointBlobTaskProgressRecalculate` and `RewardStatsPanelDraw`, and clears the temporary global block at `DAT_0055299c`.

`ResolvedEntityOperationDispatch @ 0x00460910` resolves a named entity operation through `FUN_0042e8b0` and, on success, dispatches it through `FUN_00437460`; otherwise it returns zero. `CheckpointBlobTaskProgressRecalculate @ 0x00460950` converts eight pairs of accumulated/target fields into percentages (using 100 when a denominator is zero and clamping values above 100), combines task percentages according to their counts, bounds the aggregate at the total possible score, and adds the existing completion value at `+0x1c0` to the final percentage. These are numeric aggregations; the semantic names of all underlying counters are not recoverable from this procedure alone.

The helper writes feeding this snapshot are explicit: `RewardScoreAdd @ 0x00462800` increments `DAT_0055573c` and adds its argument to `DAT_00555738`; `GlobalFloatAt00554adcAddOne @ 0x00462830` and `GlobalFloatAt00554efcAddOne @ 0x00462850` add one to their named globals; `GlobalCounterAt00555324Increment @ 0x00462870`, `GlobalCounterAt00555328Increment @ 0x00462880`, and `GlobalCounterAt0055532cIncrement @ 0x00462890` increment their respective counters; `GlobalFloatAccumulator_00555330Add @ 0x004628a0` adds its argument to `DAT_00555330`; and `GlobalFloatAccumulate_00555120 @ 0x004628c0` adds its argument to `DAT_00555120`. The broader gameplay meanings of these counters require their writer/caller traces.

## Reward display, controls, and transitions

`RewardStatsPanelDraw @ 0x00460f00` requires the active level and checkpoint blob, formats the statistics, creates/configures a draw context, and draws the score and completion/failure/quit text using the selected text resources. `RewardStatsTextFormat @ 0x00461070` converts a series of blob values to integers and strings, formats elapsed time into hour/minute/second text, and stores the display strings back in the blob. `RewardScreenTick @ 0x00461410` requires the level and blob, checks reward input, then runs a timed display loop: it advances FLIC state, draws eligible task resources, draws task text, hit-tests zones, applies transition state, and expires the pointer override. After the loop it releases loaded FLIC contexts and restores normal pointer/input state; the completion-side path also plays queued audio and updates the interface.

`RewardDisplayTick @ 0x00461790` draws task images, box images, FLICs, and text according to the per-task flags and global display switches; it lazily loads FLIC context when needed. `RewardScoreTaskTextDraw @ 0x00461c90` draws the score task text for level status 1 and performs additional formatting/drawing for the task text stored in the blob. `RewardZoneCheck @ 0x00461dd0` tests the SaveButton and AdvanceButton rectangles. A Save hit enters `SaveMenuOpenFromReward`; an Advance hit sets an output transition value and calls `CheckpointStep` directly. This agrees with [Finding 44](44-reward-buttons-use-separate-save-routes.md), correcting the older summary in Finding 09 that conflated the two routes.

`SaveMenuOpenFromReward @ 0x00462030` enters the save-menu/modal input path and conditionally updates save context based on menu state and selection; it is not a direct alias for `CheckpointStep`. `CheckpointStep @ 0x00462270` advances the campaign save context: it updates the current level record, initializes the default slot-5 context when no current record is selected, clears a record-sized region in the default context in that path, commits save state, and refreshes the level tree. Detailed file serialization and commit callers are in Finding 08.

`RewardScreenTransitionTick @ 0x00462390` watches input/control globals and, on a transition, resets display-loop outputs and reloads each task FLIC context. `RewardFlhContextReload @ 0x00462460` frees a task's current FLIC context and reloads it only when the task FLIC flag is set. `RewardFlhContextTick @ 0x004624a0` advances the timed task display, increments the task index, plays associated audio when available, and reloads contexts at the end of the sequence. `RewardTaskTextDrawAndScoreGate @ 0x00462600` sets an output gate at selected end states (subject to reward-display/FLIC conditions) and draws text for visible task entries. `PointerOverrideExpiryTick @ 0x00462700` restores pointer state, clears the override global, updates pointer position/effect duration, and pumps the input/render helper. `RewardSaveButtonZoneCheck @ 0x00462780` checks current level/blob and the save-display condition; on its active path it waits for relevant input state to settle, clears the pointer override, queues a sound, and returns 1; otherwise it calls `CheckpointStep` and returns 0.

## Limits and follow-up slices

These procedures join configuration and temporary task records to map-derived aggregates, reward-screen presentation, and campaign save transitions. The checkpoint blob is freed after the reward tick in the observed `KeepRunning` path, while the save/advance routes are separate. Numeric task fields and counter meanings should remain tied to their observed callers/writers until more evidence is traced.

Useful follow-ups: map every writer of the score/stat globals to gameplay events; establish whether each percentage denominator is a configured quota, map total, or display-only target; trace the Save-menu selection through all slot outcomes; and reconcile the blob's per-frame lifetime with the separately persisted per-level record documented in Finding 08.
