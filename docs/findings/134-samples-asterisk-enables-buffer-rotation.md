# Finding 134 — Asterisk-Prefixed Sample Entries Enable Three-Buffer Rotation

The `Samples` parser treats a leading `*` on a sample path as a Boolean argument to `FUN_0047a870`, independently of the `@` streamed-playback marker. On the ordinary WAV path, `FUN_0047a870` forwards that Boolean through `FUN_0047b580` to `FUN_0047b6c0`. A true value makes the DirectSound loader create two duplicate buffers beside the primary buffer at sound-record offsets `+0x120`, `+0x124`, and `+0x128`. After load, the bank entry receives flag `0x4`. At playback, `FUN_0047ad70` increments and wraps a per-entry index across those three buffer pointers when flag `0x4` is set.

This corrects finding 107's earlier description of `*` as a loop argument: the observed data flow reaches duplicate creation and playback selection. Static evidence establishes the three-buffer rotation, but not the intended audible effect or whether the buffers actually overlap audibly under a particular DirectSound runtime.

The shipped `Lego.cfg` has 13 active asterisk-prefixed sample paths in its `Samples` section: `SFX_Drill`, `SFX_DrillFade`, `SFX_RockBreak`, `SFX_FallIn`, `SFX_Lava`, `SND_dump`, `SND_land`, `SND_dig`, `SND_hammer`, `SND_dynamite`, `SND_pilotdrill`, `SND_Pilotdrillfade`, and `SND_TeleUp`. Some keys also begin with `!`; that key marker is separate from the `*` on the sample path. The config has no active entry combining `@` and `*`, so the streamed-plus-duplicate interaction is not established by shipped examples.
