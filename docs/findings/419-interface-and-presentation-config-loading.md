# Finding 419 — Interface and Presentation Config Loading

These 11 assigned procedures form a connected but not single-purpose loading path. `GameConfigCallbackRegistryInit` registers `GameConfigInit` as the engine's initialization callback. That initializer parses `Lego.cfg` and stages several UI, message, sound, name, and encyclopedia resources. A separate map-load path calls `TextureSetConfigLoad`, and `LevelLoad` sets the global slide threshold through `GlobalConfigValueSet`. The encyclopedia text reader is serviced from the engine tick. The evidence below separates these call paths rather than implying every assigned function runs in one startup pass.

| `0x0041fa20` | `GameConfigCallbackRegistryInit` | Clears the `0x3be`-dword block at `DAT_005560c0`, stores its argument in `DAT_005560c4`, calls `FUN_004783d0`, then registers `GameConfigInit`, engine tick `LAB_004232e0`, and a shutdown callback through `FUN_00477fd0`. The shutdown target is `LAB_00424d00` when `DAT_00505f88 == 10`, otherwise `LAB_00424cf0`. `WinMain` calls this registration routine (Finding 02). |
| `0x0041fb50` | `GameConfigInit` | The registered initialization hub. It creates the `Lego.cfg` entry tree, reads global config values, initializes fonts and interface state, and fans out to the assigned sound, object-name, encyclopedia-file, text-message, panel, and button-layout loaders. The calls occur at distinct points in a large initializer; this is not a standalone config parser. |
| `0x0040e490` | `EncyclopediaConfigFilesOpen` | Allocates and zeroes four handle arrays sized by `DAT_0055627c` through `DAT_00556288`. For each slot it resolves a name from `DAT_005561e8` through `DAT_005561f4` under the `Encyclopedia` section and opens the resulting path for reading. It also resolves and opens the `PowerCrystal` and `Ore` entries into separate globals. `GameConfigInit` calls it after the object-name loaders. |
| `0x0040e7f0` | `FUN_0040e7f0` | During the engine tick, checks the encyclopedia state bits in `DAT_004c7ea8` and a UI condition. When the selected entry is marked for refresh, it rewinds the current handle `DAT_004c7ea0`, reads up to 512 bytes per line, sends each line to the UI text routine, clears the refresh bit, and updates the UI. With a null handle it displays “Object has no encyclopedia file.” The selector at `0x0040e700` chooses a handle from the arrays opened above and sets the state bits. |
| `0x0040f5e0` | `GlobalConfigValueSet` | Stores its argument in `DAT_004a1ee4`. `LevelLoad` parses `NumberOfLandSlidesTillCaveIn`, substitutes `3` if the parsed value is zero, and calls this setter. The erosion cell update compares its accumulated counter against this global before invoking `ErosionEightNeighborPropagate`; this ties the config value to a threshold, though the source does not explain the user-facing meaning of “number of landslides.” |
| `0x0042bb60` | `TextureSetConfigLoad` | Called by the map-load pipeline for a map's texture-set entry. Reads `SurfTextWidth` and `SurfTextHeight`, writes the resulting dimensions at record offsets `+0x74/+0x78`, then requires `MeshBaseName`, `TextureBaseName`, and `RoofTexture` entries to complete the surface/mesh setup. It returns success only after the required setup succeeds. This is map resource setup, separate from the global `Lego.cfg` startup fan-out. |
| `0x0042da20` | `ObjectTheNamesLoad` | Builds parallel duplicated-string arrays from the `ObjectTheNames` section, using the same per-category counts and name tables used by `ObjectNamesLoad`. `LocalizedObjectTheNameGet` at `0x00439790` reads these arrays by category and index. `GameConfigInit` calls this beside `ObjectNamesLoad`. |
| `0x004345f0` | `PanelsConfigEntryApply` | Formats `Panels_%d_%d` using the current display dimensions, walks matching entries, resolves each entry key to a panel through `FUN_0045a370`, parses its comma-separated value, registers a panel name, converts four numeric fields, and applies the resulting packed value through `FUN_0045a650`. It is called by `GameConfigInit`. |
| `0x00434710` | `PanelButtonLayoutConfigLoad` | Loads the `Buttons%ix%i` configuration path for the current display dimensions. It resolves panel and button names, splits the entry values, converts four numeric fields, builds records, and dispatches the per-panel data to `PanelTextureSlotsAllocate` at `0x0045ac30`, which allocates the panel's `0x2c`-stride rows and loads referenced texture handles. The recovered stack-variable expressions are noisy; the exact semantic labels for the four values and each texture slot are not established here. Called by `GameConfigInit`. |
| `0x00434a50` | `SoundSamplesConfigLoad` | Walks the `Samples` section while enabling temporary alias registration. It strips a leading `!`; when its Boolean argument is false, it skips those entries, otherwise it resolves the alias and registers the configured path(s). `GameConfigInit` passes `((DAT_00505f84 & 0x100000) == 0)`, so `-reducesamples` disables `!` entries. Finding 143 traces this behavior and the shipped-config counts; Finding 178 documents the dynamic alias table. |
| `0x00434af0` | `TextMessagesConfigLoad` | Reads `TextMessages` entries by resolving each name to a message identifier and assigning its plain text. It then reads `TextMessagesWithImages`, splits each value into three tokens, and passes those tokens with the identifier to the image-message setter. `GameConfigInit` calls it before applying display-sized panel settings. Findings 248 and 252 document adjacent message-slot behavior. |

## Data and control flow

The direct startup chain is `WinMain` → `GameConfigCallbackRegistryInit` → callback registration → `GameConfigInit`. Within `GameConfigInit`, config-tree lookups are mixed with direct initialization and resource operations. The relevant call sites establish that it invokes `SoundSamplesConfigLoad`, `ObjectTheNamesLoad`, `EncyclopediaConfigFilesOpen`, `TextMessagesConfigLoad`, `PanelsConfigEntryApply`, and `PanelButtonLayoutConfigLoad`; Findings 243 and 248 already detail the last two loaders and the config helper conventions.

The encyclopedia path has a second, frame-driven leg: `GameConfigInit` opens and stores handles; `TerrainChoiceResourceSelect` chooses one and marks state; `EngineTick` calls `FUN_0040e7f0`, which reads the selected text when refresh is pending. This is supported by the selector and tick call sites in the decompiles. The interpretation as an encyclopedia display follows from the config section and literal error text; other meanings of the numeric type cases remain unresolved.

Two config consumers are outside this startup chain. `LevelLoad` supplies `NumberOfLandSlidesTillCaveIn` to `GlobalConfigValueSet`, then erosion code consumes the stored threshold. The map load pipeline calls `TextureSetConfigLoad` for its current texture-set entry, where dimensions and resource names determine whether subsequent map setup continues. These neighboring flows show that the assigned area label groups config/resource work, not one runtime phase.

## Unresolved questions and follow-up slices

- The identity and meaning of each encyclopedia category count/table are not fully established from these routines alone; a focused pass could trace their initialization and all selection call sites.
- `FUN_0040e7f0`'s direct caller appears only in the legacy engine-region excerpt, while the full corpus contains the function body but omits that caller edge. Confirming the tick relationship in a complete reference inventory would improve call-graph coverage.
- `PanelButtonLayoutConfigLoad` has compiler/decompiler stack artifacts. A focused pass over its raw instructions and the `PanelTextureSlotsAllocate` consumer could identify the four numeric fields and texture-slot meanings without guessing.
- `TextureSetConfigLoad`'s required-key failure cases are visible, but the map loader's broader fallback/error policy is a separate map-resource-loading slice.
- `GlobalConfigValueSet` and its consumer establish a numeric erosion threshold; the domain meaning and any configuration bounds are not established here.
