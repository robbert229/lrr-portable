# Finding 472 — Entity Motion and Action Execution

This finding maps the 36 procedures assigned to entity-motion-actions. Direct behavior is described from the canonical pseudocode; opaque flags and callback contracts remain unlabeled unless neighboring code supports the interpretation. The central flow is: route setup stores a list of step records on the entity, `PathStepAdvanceAndArrivalCheck` advances that list, `StepMovementVectorResolve` turns the active record into a movement vector, and `EntityMovementAccumulatorApply` applies movement while checking terrain and nearby entities.

## Route and action state

`EntityRouteSetupAndMarkerAssociate @ 0x00441700` allocates 0x14-byte records for the supplied route cells, writes each cell and within-cell coordinates, and initializes per-step flags. For a final action record it gets a point from the supplied object; on intermediate steps it may randomize within-cell coordinates for entities with the relevant flag. It associates a route marker for each step and can mark a step when a route transition returns value 2. If route construction succeeds, it calls EntityActionSequenceReset(entity, 0), clears entity flag 0x400, sets entity flag 1, stores the record pointer/count, and zeros progress fields. If a route marker cannot be made, it frees the temporary record array and returns failure.

`EntityActionSequenceReset @ 0x00441940` releases any current sequence. On its zero mode it scans remaining step kinds to clean up a linked kind-5 entity, removes activities 4 and 10 for kind 3, optionally performs a coordinate update, and calls helper FUN_004040a0. On nonzero mode for kind 2 it restores a saved pose. In either mode it frees the route records, resets count/index/progress fields and selected state bits, clears a linked entity flag when present, and requests activity 0. `EntityStateReset @ 0x00441b30` calls this reset, optionally detaches linked records, handles reciprocal state bits between an entity and its +0x3c0 partner, clears flag groups, performs kind-specific cleanup (including route/activity 0x1d and activity record removal), and when requested refreshes records, activity, and scene state.

`EntityType5FinalizeIfAllowed @ 0x00441ea0` finalizes kind 5 through FUN_0040bde0 and FUN_00437540 only when global bit 2 is clear. `EntityFaceTargetActionStart @ 0x00441ed0` starts only for kind 3, with no active route and either no positive timer or global mode bit 4. It resets the route/action state, resolves the two entities' poses and centers, normalizes the vector from the source center toward the target center, and dispatches that vector through EntityVelocityVectorDispatch. It requests activity 0x2c and updates scene state for action selectors 1–3, setting a selector-specific bit at +0x3e4; it stores the target position and direction components in the entity. The calculations establish facing direction, while the gameplay meaning of the three selectors remains unknown.

`KindEffectSlotInitDispatch @ 0x004420d0` gets the entity's pose and height and dispatches effect creation for kinds 1–4 using the Lazer, Pusher, and Freezer resources. `EntityActionRouteStateInitialize @ 0x00442210` resets entity state, requests activity 0x4d, updates scene state, sets entity flag 0x100000 when that update succeeds, and initializes timer +0x340 to -1. `EntityType3Flag04000000Test @ 0x004436f0` is a predicate for kind 3 plus bit 0x04000000 in +0x3e8. `TryRandomEntityActionFromCodeRange @ 0x00443670`, when entity bit 0x400 is clear and it has no route, tries up to five random activity codes from 0x38–0x4c; the first successful activity request sets entity flag 0x8000.

## Pose, vectors, and movement

`EntityTransformPositionGet @ 0x00442260` takes the entity and two separate output pointers, then returns pose x/y through the entity's scene transform. The mapped port exposes this three-argument target body and keeps a two-float-buffer convenience helper for other callers. `SurfaceVectorNormalize @ 0x004422a0` reads a two-component surface vector and normalizes it. `VectorDirectionAngleRadiansGet @ 0x00442480` normalizes that vector, obtains its angle, and reflects it around 2π when x is negative. `EntityPositionToTerrainCell @ 0x004424f0` resolves the entity pose to a terrain cell; `GridOperationArgumentAdapter @ 0x00442540` forwards arguments to the grid operation adapter.

`EntityVelocityVectorDispatch @ 0x00442300` sends a supplied 3D vector to the kind-specific pose/physics component for kinds 1–4 (or a scene transform for the flagged fallback), then stores that vector in the entity's velocity fields and computes the corresponding -1% offsets. A null vector constructs a default direction using the supplied argument. `SubobjectPoseDeltaNormalizeAndDispatch @ 0x004425f0` reads the current subobject orientation for kinds 1–3, computes a normalized delta toward the requested orientation when it changes, and sends the adjusted direction and destination through the relevant pose component. `EntityWorldPositionSet @ 0x004428a0` writes position to the kind-specific pose component, optionally initializing orientation first, then updates cached direction and offset fields.

`EntityMovementTickScaleAndDeltaGet @ 0x00446610` obtains the kind-specific movement scale and calculates movement and tick delta from the entity's base scale, state bits, terrain cell properties, and frame delta. Some entity kinds use fixed delta. For ordinary movement it applies reductions for terrain and particular kind-2 terrain state, and scales both outputs by frame delta; kind-4 entities with a state combination and bit 0x8000 receive an additional delta multiplier.

`EntityMovementAccumulatorApply @ 0x00442b10` consumes accumulated turn, forward, and vertical inputs. It updates orientation/velocity, checks the destination cell and nearby entities through EntityFlagGatedCallbackDispatch, tests terrain and obstruction predicates, and either restores the original pose or resolves an allowed position. It may request route/activity changes when a route marker blocks movement, and returns a small result code; only when nonzero does it write the delta output. It always clears the three consumed input accumulators. `EntityPoseOrientationDispatch @ 0x00442f80` synchronizes kind-specific pose orientation; kind 2 resolves a nearby valid point and turns toward it, while kinds 6, 7, 8, 9, 0xb, and 0xd update scene-transform rotation/height over time unless a pose override is active. `SceneObjectPosePositionSync @ 0x00443510` copies position and orientation from the entity pose to its linked scene object when the values differ.

## Route candidates and path-step advancement

`AdjacentPositionCandidateFind @ 0x00443710` first rejects an acceptable current cell, then runs the route search twice with EntityRouteCellCandidateAccept as its predicate and returns the selected predecessor cell. `EntityRouteCellCandidateAccept @ 0x00443840` accepts only cells passing the terrain/route checks, occupancy predicate, and an additional cell test; when its in/out flag is zero it first rejects cells with an existing route marker. The individual predicates' meanings are unresolved.

`PathStepAdvanceAndArrivalCheck @ 0x004438b0` is the route-list state machine. Once progress reaches the current step threshold, it maps step kind (2–0x15) into specific entity flags or actions, handles the route-end and lookahead markers, then calls EntityActionSequenceReset(entity, 1). It advances progress using EntityMovementTickScaleAndDeltaGet, updates path interpolation, and checks arrival conditions for step kinds 3, 9, and 0xc. It also checks nearby entities and can reset the route and request activity 0x20 when the relevant entity flag is set. `StepMovementVectorResolve @ 0x00444680` reads the active step record, advances the index when asked, resolves target positions, perturbs coordinates for blocked cells, and derives a movement vector from step flags. It can encode a fixed cardinal direction, use the stored within-cell offset, or point toward the step target; it updates heading and activity state when an obstruction changes the selected direction.

## Movement-driven state and callbacks

`LinkedEntityFlagAndCommandUpdate @ 0x004440a0` checks the target at +0x2fc; for a kind-4 target it sets bit 0x40 on both entities and sends operation 0x1c to the source. `ActivityTimeoutAccumulateAndRaise @ 0x004440f0` runs when entity bit 0x400 is set (and a kind-3 subtype check passes). It compares two helper-provided values and, under additional bit and terrain conditions, clears a counter, sets flags, and requests activity 0x22; otherwise it adds the frame delta to its accumulator. If its outer gate fails, it detaches linked records.

`EntityRandomCellStepRouteIssue @ 0x00444260` tries up to 16 random neighboring cells. For a cell passing route checks, it picks a point inside the cell, searches a path from current to candidate, and installs the result with EntityRouteSetupAndMarkerAssociate. `FlaggedVectorStepCommandIssue @ 0x00444460` requires no route, an accepted task/selection state, and a current terrain cell that is not already occupied by the route predicate. It resets state, offsets current position by the supplied vector times a global scale, finds a valid destination and path, and installs the route; on success it flags the final step and requests follow-up state through FUN_00407450.

`EntityEnterEvent21StateOnce @ 0x00444620` runs once when its entity flag is clear and the linked slot at +0x36c is empty. It resets state, sets the guard flag, requests activity 0x21, updates scene state, and registers the entity. `EntityDispatchEvent31ForPendingFlag @ 0x004437f0` handles kind 3 when +0x3e8 bit 0x80000000 is set and +0x3e4 bit 0x20000000 is clear; it sets the latter guard bit, requests activity 0x31, and updates scene state. `EntityTurnToVectorActivityIssue @ 0x00444fb0` is kind-2-only: it normalizes the current and requested horizontal vectors, clears the existing action sequence, selects turn action 9 or 10 (or 0x14/0x15 when bit 0x400 is set), and starts the chosen activity; the sign of the cross-product sets an additional flag for one direction.

`EntityPathStepVectorNormalize @ 0x004451e0` adjusts stored path points when entity bit 0x20000000 is set, excluding step kinds 3, 5, 6, and 7. With flag 0x80 it first dispatches a callback, then adjusts each point that passes the cell checks toward a generated point 0.71 units from the checked coordinate. `EntityMoveVectorSurfaceProbe @ 0x004455a0` rejects a current invalid cell, projects a normalized fraction (one third) of the movement vector ahead, and returns whether the projected cell is invalid or fails the surface test. `EntityBehaviorCallbackTick @ 0x004456e0` dispatches a callback for kind 3; for kinds 8 and 0xd with bit 0x10000, it calls another callback when the transform's remaining interval is below 75. `EntityFlagGatedCallbackDispatch @ 0x00445d70` calls callbacks LAB_004460f0 and LAB_00445df0 when helper-derived flag bits 0x100 and 0x80 are present, returning a local result initialized to zero. The callback effects are outside these procedures.

## Unresolved questions and follow-up slices

- Identify the semantics of route-step flags, entity masks, and helper predicates used for terrain, occupancy, and movement permission.
- Trace the callback bodies dispatched by EntityFlagGatedCallbackDispatch and EntityBehaviorCallbackTick.
- Resolve the movement return codes from EntityMovementAccumulatorApply and determine how callers interpret each code.
- Determine which entity kinds and scene objects share the cached velocity and pose fields.
- Trace the action selector and state bits written by EntityFaceTargetActionStart and the route completion cases in PathStepAdvanceAndArrivalCheck.
