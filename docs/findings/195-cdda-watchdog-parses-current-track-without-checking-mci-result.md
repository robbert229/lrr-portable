# Finding 195 — CD-Audio Watchdog Parses Track Status Without Checking MCI Success

`FUN_00489280` asks MCI for the current CD track and stores the `mciSendStringA` result code in `DAT_00544a1c`, but it does not test that code before parsing the output buffer as an integer. The parser `FUN_0048dad0` returns zero when the input has no leading decimal digits. For a nonnegative selected track index, `0 <= selectedTrack + 1`, so an empty or nonnumeric result can make the watchdog report playback as valid and skip its restart/callback path. The output buffer is shared across the two status commands and is not cleared here, so an MCI error may also leave previous text to be parsed. This is a conditional failure-path behavior; no MCI error was induced at runtime.

**Evidence.** Shipped `reference/LegoRR.exe`, SHA-256 `c3d8ce23f1aa21814950c77e713ec176599506d4e71758cf1cf709525e581e0f`. `FUN_00489280` at `0x489280` issues `status cdaudio current track`, stores the MCI result code, calls `FUN_0048db70`/`FUN_0048dad0` to parse the shared output buffer, and returns valid when the parsed number is at most `param_1 + 1`. `FUN_0048dad0` at `0x48dad0` returns zero when no digits are present. Microsoft's [MCI command-string documentation](https://learn.microsoft.com/en-us/windows/win32/multimedia/command-strings) says `mciSendString` returns zero on success and an error code on failure.
