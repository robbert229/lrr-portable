## G98-015 (`view.cpp`)

**Blocker.** Finding 552 left it. The group
`#if defined(LEGORRR_BACKEND_WINAPI) && defined(_WIN32) && !defined(_WIN64)`
(then at `view.cpp:1816`, previously `3122`) held three kinds of item:

- the `#include "lwsc_winapi.hpp"`;
- the annotated `scene_runtime_user_visual_manager` (`0x004827f0`);
- the port's winapi scene runtime: `s_scene_camera_bindings` and six more
  statics and helpers, and `scene_runtime_initialize` through
  `scene_runtime_light_parameter_set`.

The group could not move whole, because it held an annotated function
besides other items.

**Reshape.** The group closes and reopens twice under the same condition
(addendum kind 5):

1. an include-only group (`lwsc_winapi.hpp`), which the tool copies into
   the unit file;
2. a single-branch group around the annotated function alone, which moves
   whole, with a guarded declaration (#540's rule);
3. the port helpers, which stay in `view.cpp`.

`python3 tools/reshape_check.py src/gods98/view.cpp --base HEAD --head worktree`:

```
src/gods98/view.cpp:
  includes: identical
  native: identical
  matching: identical
  mingw: identical (emulated: host gcc + reference defines)
  object: identical (including .drectve when present)
```

**Tool defect.** The first G98-015 relocation failed the native build (and
would have failed the matching build). The defect:

- The closure variable `s_portable_model_render_dispatch_ops`
  (`surface.cpp`, unconditional) is initialised with eight static helpers
  (`portable_model_render_first`, …).
- Helpers go last in the unit file, so the tool forward-declared them, but
  it always put the forward declarations after the data. The initializer
  named them first.

The fix puts the block before the first variable, prototype or group that
names a forward-declared function. Types and macros never count: a macro
body needs no declaration, and the declarations may need the types. Units
whose data names no forward-declared function generate exactly as before.
G98-002's output (generated with the old tool) is therefore unchanged by
the fix: its data names none, or its native build would have failed.

**G98-005 (Main.c), the one unit left.** Its functions are in
`src/platform/winapi/entry.cpp` and `src/platform/winapi/frameloop.cpp`,
which build for the winapi backend only:

> src/platform/winapi/entry.cpp builds for the winapi backend only
> src/platform/winapi/frameloop.cpp builds for the winapi backend only

`#if` block and no reshape inside one file fixes it. It needs a decision on
where a backend-only original unit lives in the link-order list (or a
native counterpart for the entry point), so it is left for a follow-up.
It has been reported unchanged since finding 523.
