# Finding 397 — CRT Strings, Locale, and Formatting

This finding maps the 61 functions assigned to `platform-and-runtime/runtime-strings-locale-and-format`. Evidence is the canonical decompile corpus at `docs/decompiles/full/LEGORR.full.c`. Caller/callee claims refer to direct calls in that corpus unless marked as an inference. The area contains CRT compatibility routines and game-facing string/config helpers; several aliases and ABI details remain unresolved, so descriptions follow the recovered operations rather than assuming modern CRT contracts.

## String primitives, parsing, sorting, and output

- `StringCaseSubstringFind @ 0x0048c040` scans a string for the first case-insensitive substring match using `__strnicmp`; optional outputs receive the match offset and needle length. It returns the match pointer or null. `LwoSurfaceSettings @ 0x0048c820` calls it.
- `StringFindSubstring @ 0x0048da50` returns the haystack for an empty needle, uses aligned word-at-a-time scans for one-byte needles, and otherwise walks candidate starts and compares bytes until the needle ends or the haystack does. Callers include `BuildingTypeConfigRecordParse`, `DDiSceneResourceNameResolve`, `WinMain`, and `SceneEntrySlotTableExpand`.
- `StrChr @ 0x004914a0` searches for a byte, returning its address or null; it has aligned word-at-a-time fast paths. `CrtMultibyteCharacterSearch @ 0x0049b5b0` delegates here when no multibyte code page is active and otherwise advances by one or two bytes according to the lead-byte table.
- `_strncmp @ 0x0048f270` compares at most the requested number of bytes and returns the observed CRT-style ordering result. `__strnicmp @ 0x0049dab0` performs a bounded case-insensitive comparison, using ASCII folding when locale state is inactive and `CrtCharacterToLowerLocale` otherwise. `__strcmpi @ 0x0048ff10` applies the same two-mode pattern for whole strings. The current full corpus does not show direct callers for `_strncmp` or `__strcmpi`. `StringCaseSubstringFind` directly calls `__strnicmp`, and `LwoSurfaceSettings` calls the substring helper.
- `_strncpy @ 0x0048e770` copies up to the count, stops at NUL, and zero-pads the remainder. It has aligned word-copy optimizations. `DbcsAwareBoundedStringCopy @ 0x004976d0` delegates to it when the active code page is zero; otherwise it copies a lead byte and its following byte together, avoids leaving a dangling lead byte at the bound, and zero-pads remaining capacity.
- `BoundedStringLength @ 0x00493ec0` returns the string length up to the bound, or the bound if no NUL occurs before it. `WideStringLength @ 0x00499710` counts UTF-16 code units up to NUL. `BoundedWideStringLengthIncludingNull @ 0x0049add0` returns the count including NUL when found within the bound, otherwise the bound.
- `CrtStringDuplicate @ 0x0049b660` allocates and copies a NUL-terminated byte string, returning null for null input or allocation failure. `StringPrefixReserve @ 0x004907c0` shifts a NUL-terminated string right by the requested prefix length using `memmove`-style `FUN_00498000`; float formatting routines call it to make room for a sign/prefix.
- `ArraySortWithComparator @ 0x0048de20` implements an iterative quicksort-like sort over fixed-size records using a supplied comparator, swapping the midpoint into the pivot position, partitioning, and keeping pending subranges in local arrays. Partitions of at most eight elements go to `QsortSmallPartitionSort @ 0x0048dfd0`, which selects/comparisons records and swaps them into order. `ByteRangeSwap @ 0x0048e030` exchanges `count` bytes between distinct ranges. Callers of the sort include command-chain cleanup and terrain/spatial search paths; the comparator and record semantics vary by caller.
- `ParseSignedDecimal @ 0x0048dad0` skips classified whitespace, accepts an optional sign, and accumulates decimal digits into an `int`; it does not expose an end pointer or an overflow/error result in this body. `ParseIntegerWrapper @ 0x0048db70` forwards to it. The parser is also used by timezone environment parsing.
- `ParseFloat @ 0x0048d980` skips classified whitespace, computes the remaining NUL-terminated length, calls the numeric conversion helper `FUN_004907f0`, and returns the double result as `float10`. It is used by numerous game config, menu, level, movie, and rendering config readers.
- `MarkupIntegerTokenParse @ 0x0048e890` builds a bounded input stream around a NUL-terminated token and calls `CrtFormattedScanV @ 0x00493ef0`; `ObjectiveAdvisorTokenLoad` is its direct caller.
- `NumberStringScanParse @ 0x00498350` parses a numeric byte string through sign, integer, fraction, and exponent states, accepts the active decimal-point byte, collects up to 25 significant digits, adjusts the decimal exponent, and converts the mantissa/exponent into an extended-float representation through `CrtDecimalDigitSequenceToExtended96` and `ExtendedFloatPowerOfTenScale`. It returns status values and writes fields through its output record. `FUN_004907f0` and extended-float conversion helpers call it.
- `SignedDecimalToStringConvert @ 0x0049db60` handles a negative base-10 input by asking `CrtUnsignedIntegerFormatRadix` to add a sign; other values/bases are sent as unsigned. `CrtUnsignedIntegerFormatRadix @ 0x0049dba0` repeatedly divides by the radix, writes digits (with alphabetic digits for values above nine), optionally prepends `-`, NUL-terminates, and reverses the produced digits. This body does not validate a zero radix.
- `StringToLowercase @ 0x0049dc10` and `StringToUpper @ 0x0049dcd0` modify the input buffer in place. With locale state inactive they fold ASCII letters; with locale state active they call `LocaleCharacterMapString` into a temporary buffer, copy the result back, and free the temporary. The locale mapping call can change byte length, so the allocation size is taken from the conversion helper's result.

### Formatted output and input helpers

- `FormattedStringOutput @ 0x0048d9e0` builds a string-output record with flags `0x42` and a very large count, invokes `EngineFormatStringToStream`, then writes a terminating NUL when the count remains nonnegative. Its overflow/error branch calls the body at `0x004908a0`; the assigned alias there is misleading in this corpus and is documented in Finding 395. This wrapper is used broadly by config, menu, resource, and startup code.
- `EngineFormatStringToStream @ 0x004909d0` parses a printf-style format, advances a caller-supplied varargs cursor, and emits ordinary characters and formatted fields through the buffered character/string/repeat helpers. Its recovered cases include flags, numeric width and precision or `*` arguments, length modifiers (`h`, `l`, `w`, `I64`), character/string and wide-character/string forms, signed/unsigned/octal/hex/pointer conversions, floating conversions through function pointers, and `%n`. It handles sign/prefix/precision/width padding before emitting each converted field; DBCS bytes are emitted as a pair when the active ctype table marks a lead byte. Direct callers include `FormattedStringOutput`, `FormattedTextBufferBuild`, and the stream setup helper from Finding 395.
- `CrtWideCharToMultibyte @ 0x00498b70` converts one wide character to the current multibyte code page, or copies a single byte when locale state is inactive; failed/unrepresentable conversion sets the CRT error global and returns `-1`. `EngineFormatStringToStream` calls it for wide-character output.
- `CrtMultibyteToWideChar @ 0x00498e00` converts the first multibyte character, honoring the active maximum character width and lead-byte table. It returns zero for empty input, one for a single-byte character, the configured width for a successful multibyte conversion, or `-1` with the CRT error global on invalid/incomplete sequences. `CrtFormattedScanV` calls it for wide-character scanning.
- `CrtWideCharToMultiByteCompat @ 0x0049abe0` converts a NUL-terminated wide string or a bounded prefix to the active code page. With locale state inactive it copies values below `0x100`; otherwise it uses `WideCharToMultiByte`, handles insufficient destination space by converting one wide character at a time, and sets the CRT error global on conversion/default-character failure. With a null destination it reports the source length or the converted byte count excluding the terminating NUL. `CrtTimeZoneStateInit` uses it for Windows timezone names.
- `CrtCharacterClassFlag8Check @ 0x00498f00` tests ctype flag `8` through the byte table or `CharacterClassifyMask`; formatted scanning and whitespace skipping call it.

## Locale, code pages, character classes, and comparisons

- `CrtAnsiCodePageTablesInit @ 0x004965c0` requests the ANSI code page by calling `CrtLocaleCodePageTableUpdate(-3)`. CRT `entry @ 0x0048f000` calls this during startup.
- `CrtCodePageGet @ 0x004964e0` maps selectors `-2` and `-3` to OEM and ANSI code pages and records a mode global; selector `-4` returns the current ANSI code page global. Other values pass through. `CrtLocaleCodePageTableUpdate @ 0x004962f0` resolves the selector, reuses the current tables if unchanged, resets them for code page zero, loads one of the embedded tables when matched, or queries `GetCPInfo` and constructs lead-byte/ascii flags for other code pages. It also updates the LCID and embedded locale fields. If querying a code page fails it either returns `-1` in explicit-code-page mode or resets the tables.
- `CrtCodePageLocaleIdLookup @ 0x00496530` maps the recognized code pages `0x3a4`, `0x3a8`, `0x3b5`, and `0x3b6` to LCIDs `0x411`, `0x804`, `0x412`, and `0x404`; other code pages map to zero.
- `CrtCtypeTablesReset @ 0x00496590` clears the ctype/lead-byte table and locale/code-page globals. `CrtLocaleCodePageTableUpdate` calls it for a zero code page and selected failure paths.
- `CrtCharacterClassFlagTest @ 0x00495db0` checks a byte flag in the ctype table and, if absent, checks a requested class mask in the secondary table. `IsDbcsLeadByte @ 0x00495d90` is a wrapper requesting flag `4`. CRT command-line parsing and `entry` use it for multibyte command-line characters.
- `CharacterClassifyMask @ 0x0048f1d0` returns requested ctype bits from the current table for byte values; for wider values it determines the byte sequence width and delegates to `CrtGetStringTypeACompat`. `CrtGetStringTypeACompat @ 0x00496ad0` lazily probes whether the platform supports `GetStringTypeA` or only `GetStringTypeW`, caches that choice, and converts through the active code page when using the wide API. Character parsing, text helpers, numeric parsers, and case mapping call the classifier.
- `CrtCharacterToLowerLocale @ 0x004975d0` performs ASCII lowercase when locale state is inactive; otherwise it checks the ctype lowercase flag and uses `LocaleCharacterMapString` for one- or two-byte input. `__strcmpi`, `__strnicmp`, and decimal-point normalization call it.
- `CrtCompareStringACompat @ 0x0049afe0` lazily probes `CompareStringA`/`CompareStringW`. It compares directly with the ANSI API when available; otherwise it converts both strings to wide characters and calls `CompareStringW`, handling bounded lengths and some empty/multibyte cases. `CrtCountedStringCompare @ 0x0049af20` calls this helper with the current LCID/code page and returns a normalized comparison result; environment lookup and environment-entry search use it.
- `CrtLocaleDataGetOrInitialize @ 0x00497ec0` builds a decimal-format locale record from extended-float/decimal conversion state and returns a pointer into cached globals. Scientific, fixed-fraction, and float-format preparation routines call it. Despite its assigned name, the body shown is part of numeric-format locale data handling, not the main code-page/ctype setup path.

## Command-line and environment state

- `CrtEnvironmentBlockGet @ 0x00496190` obtains the process environment as wide strings when supported, otherwise ANSI strings; in the wide case it measures the double-NUL-terminated block, converts it to the current multibyte code page, frees the OS block, and returns the allocated byte block. It records which source mode succeeded in `DAT_005492b0`. CRT `entry` calls it.
- `CrtEnvironmentPointerArrayBuild @ 0x00495df0` counts non-drive-current-directory entries (excluding strings beginning `=`), allocates a null-terminated pointer array and separate copies of each included string, frees the original environment block, and stores the result in `DAT_005490f8`. Allocation failures call `__amsg_exit(9)`.
- `CrtCommandLineArgumentsInit @ 0x00495ee0` obtains the executable path as fallback argv[0], performs a first sizing/count pass and then a second fill pass through `CrtCommandLineArgumentScan`, allocates argv storage, and sets the argv pointer/count globals. CRT `entry` calls it.
- `CrtCommandLineArgumentScan @ 0x00495f80` supports quoted executable names, whitespace separators, backslash runs before quotes, doubled quotes in quoted contexts, and DBCS lead/trail-byte copying. Its output parameters let the caller size arguments first and populate them in a second pass; the argv initializer uses both modes.
- `CrtEnvironmentVariableLookup @ 0x0049ae10` ensures the CRT environment array exists, finds a name by comparing the requested name to the entry prefix before `=`, and returns a pointer/offset into the stored value or zero if not found. It calls `CrtWideEnvironmentStringListConvert` when the wide environment source is active.
- `CrtWideEnvironmentStringListConvert @ 0x0049af60` converts each wide environment entry to a multibyte string and inserts it through `CrtPutEnvUpdate`; conversion/allocation failure returns `-1`.
- `CrtEnvironmentEntryFind @ 0x0049b4c0` locates an entry by counted key comparison and verifies that the following byte is `=` or NUL; it returns the index or a negative insertion position. `CrtPutEnvUpdate` calls it.
- `CrtPutEnvUpdate @ 0x0049b2b0` parses `name=value`, `name=` deletion, or replacement; grows/clones the CRT environment pointer array as needed; and, when requested, updates the OS environment with `SetEnvironmentVariableA`. `CrtWideEnvironmentStringListConvert` calls it without the OS update flag. The function stores/retains passed strings in its CRT array on the observed paths; ownership expectations should be checked before treating arbitrary caller strings as transferred.
- `CrtEnvironmentArrayClone @ 0x0049b540` allocates a new pointer array, duplicates every entry with `CrtStringDuplicate`, and appends a null terminator. It is used when `CrtPutEnvUpdate` needs to expand the array.

## Timezone and signal handling

- `CrtTimeZoneInitializeOnce @ 0x00499860` invokes `CrtTimeZoneStateInit` once, then increments its initialized flag. `CrtCalendarFieldsToTimeScalar @ 0x00496f50` ensures this initialization before converting a calendar tuple to a scalar.
- `CrtTimeZoneStateInit @ 0x00499880` first checks the `TZ` environment variable. If it is absent, it calls `GetTimeZoneInformation`, stores the base bias/daylight offsets, and converts standard/daylight zone names. If `TZ` is present, it caches the text, parses the standard name and signed hour/minute/second offset, and optionally parses the daylight name. `ParseSignedDecimal`, `CrtEnvironmentVariableLookup`, and `CrtWideCharToMultiByteCompat @ 0x0049abe0` is a direct helper in the timezone/environment path.
- `CrtCalendarFieldsToTimeScalar @ 0x00496f50` rejects years outside its recovered range, accumulates month/day/time fields into seconds relative to its epoch and timezone bias, and optionally applies daylight-saving adjustment through `CrtDaylightSavingTimeCheck`.
- `CrtDaylightSavingTimeCheck @ 0x00499b30` computes and caches start/end transition boundaries when the year changes, then compares the time-of-day and day-of-year fields against those boundaries. `CrtDaylightTransitionBoundaryCompute @ 0x00499da0` derives a transition date either by nth-weekday rules or fixed-day rules and records the start/end day and millisecond offset globals. Exact field meanings are inferred from these repeated calculations and Win32 timezone structures.
- `CrtSignalHandlerRecordFind @ 0x0049ab90` searches the signal callback table for a matching signal record. `CrtSignalHandlerDispatch @ 0x0049aa10` selects the signal callback slot, handles default/ignore sentinel pointers, invokes the selected callback, and updates saved signal state for signals 4, 8, and 11. `_abort @ 0x004996f0` directly dispatches signal `0x16` before exiting with code 3.

## Error and state boundaries

- Code-page, LCID, ctype, timezone, argv, environment, signal, and locale-conversion state is cached in globals. The helpers update related parts of those globals in separate paths; the corpus does not prove thread safety or reentrancy for these lazy initializers.
- Several functions return CRT/Win32-style sentinels (`0`, `-1`, comparison constants) and set a shared error global on conversion/allocation failure. Callers differ in whether they propagate the sentinel, terminate through `__amsg_exit`, or continue with fallback behavior.
- `CrtCompareStringACompat`, `CrtGetStringTypeACompat`, and locale case conversion have platform capability probes. Their ANSI and wide fallbacks do not all share the same parameter conventions; only the direct argument flow is asserted here.
- `ParseSignedDecimal` and integer formatting routines do not show bounds/radix validation in their bodies. This finding records those limits; it does not establish safety for arbitrary external inputs.

## Open questions and follow-up slices

1. Verify the names and ABI boundaries for aliases whose assigned name diverges from the recovered body, especially `CrtLocaleDataGetOrInitialize`, and confirm the buffer-overflow branch in `FormattedStringOutput` against raw disassembly/callers.
2. Trace the private numeric conversion helper at `0x004907f0` and its relationship to `NumberStringScanParse`, `ParseFloat`, and `MarkupIntegerTokenParse`.
3. Establish ownership rules for strings passed to `CrtPutEnvUpdate`, and verify behavior for replacing/deleting values in the CRT and OS environment.
4. Test command-line quote/backslash and DBCS rules against the target CRT version, including malformed quotes and trailing backslashes.
5. Decode the ctype table flags and code-page table records, including the exact semantics of `DAT_005493d4` and `DAT_004aff74`.
6. Compare `CrtTimeZoneStateInit`'s `TZ` parser and daylight-boundary globals with documented Windows/CRT structures, especially southern-hemisphere transitions and fixed-date rules.
7. Trace signal registration writes to the callback table and verify default/ignore/reentrancy behavior for each supported signal.
8. Confirm the bounds and preconditions of the sort helpers, zero radix handling, and numeric parser overflow behavior.
