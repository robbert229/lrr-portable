# Finding 467 — Command Creation and Issue Routing

This finding maps several producers of task and command records, the entity-local and global lists that carry them, the placement-assignment tick, and two player-facing feedback paths. The primary evidence is the canonical pseudocode in [`LEGORR.full.c`](../decompiles/full/LEGORR.full.c). This is a bounded map of the 20 functions assigned to issue #135, with adjacent queue helpers included only where needed to explain their data flow. Function names are descriptive labels; where the checked-in decompile retains `FUN_...`, the address is the stable identifier.

Related context: [Finding 246](246-entity-move-route-command-and-object-clone-helpers.md), [Finding 256](256-command-band-step-issuers-flag-behavior-timers-and-steering-helpers.md), and [Finding 441](441-incident-and-information-message-queue.md). Finding 466, in a concurrent open PR, covers the shared command registry and links.

## Task-record producers

`EntityCommand15ValidatedRecordQueue @ 0x00402670` calls `FUN_00431560` before checking its argument. For a non-null entity accepted by `FUN_00437cc0`, it allocates record kind `0x1a`, links it to the global command list through `CmdLinkHead @ 0x00404030` with command kind `0x0f`, stores the entity at `+0x10`, and sets the observed flag mask `0x40040` while clearing bit `0x10`. A caller in the entity-kind-3 initialization path invokes this helper only after setting the entity's type-specific state; this is a gated producer, not a general-purpose command constructor.

`CmdCreateTask @ 0x00402720` allocates task record kind `3`, stores its entity at `+0x10` and its second argument at `+0x18`, then chooses a command kind from the entity's leading type value: type `6` selects kind `0x12` or `0` according to the sign bit of entity word `0xfa`; type `7` selects `1`; type `9` selects `0x10`; and type `8` stores `8` at record `+0x3c` and selects `3`. Other entity kinds retain the initialized default kind `2`. It globally head-links the record and calls `MinionCompanionCmd`.

`MinionCompanionCmd @ 0x00402850` is the companion path for entity type `6`: it allocates another kind-3 task record, stores the entity, sets task kind `0x15`, and tail-list-links it with `CmdLinkTail @ 0x00404070`, then sets flag `0x2000`. For other entity types it returns without creating a record.

`FUN_004027a0 @ 0x004027a0` requires both `FUN_00433090` and `FUN_00432c50` to return zero, then requires `FUN_0040aea0(0x0f, 0, 0)` to return nonzero. It allocates task kind `0x16`, copies two input dwords to offsets `+8` and `+0x0c`, and head-links with command kind `0x0e`. The exact semantic meaning of the copied pair is not established by this function alone.

`EntityCommand14BatchIssue @ 0x00402800` creates one or more records: a zero count is changed to one, then each iteration allocates kind `4`, initializes it through `FUN_00402060(record, 0x14)`, and tail-links it. The zero-input case additionally sets record flag `0x40`; it does not repeatedly create an unbounded batch.

`CellCommandType3Issue @ 0x00403030` requires `FUN_00432bd0(x,y)` to succeed and `FUN_00432d90(x,y)` to return zero. It then allocates kind `0x0b`, stores the coordinate pair, calls `FUN_00402600(record,1)`, head-links as command kind `6`, and sends the result of `FUN_00431570(x,y,3)` to `FUN_0044f4e0`.

`FUN_004030e0 @ 0x004030e0` first calls `FUN_0046a120` with the first input dword and returns if that check fails. On success it sets bit `0x1000` in the input record's word `+0x5c`, allocates record kind `0x13`, and, when source flag `0x100` is set, copies the source's variable-length data from `+0x10` using the count at `+0x11`, stores the count at new-record `+0x44`, and sets new-record flag `0x100`. It then sets new-record flag `0x10`, stores source pointers at `+0x38` and `+0x58`, stores the new record back at source `+0x16`, and links globally using the source's command kind at `+0x13`. This preserves a validated record and its optional payload; its downstream interpretation is outside the assigned function.

The three `CmdCreate*` functions use a different path: they append a new command record to the linked chain rooted at the entity's `+0x2f0` field. `CmdCreateMove @ 0x004035c0` allocates kind `0`, stores x/y at `+8/+0x0c` and its third argument at `+4`, then uses `FUN_00404190`'s result as the insertion point; when that result is zero, it installs the record as the head and calls `FUN_00407450(entity)`. The caller treats the helper result as a chain insertion point, although its checked-in decompile only shows traversal and no explicit return value, so the exact tail-selection behavior is unresolved. `CmdCreateGated @ 0x00403610` does nothing unless entity flags at `+0x3e0` include `0x400`; when admitted, it allocates kind `5`, stores the supplied value at `+0x10`, and appends it, but does not call the startup helper on the empty-chain path. `CmdCreateTarget @ 0x004036c0` allocates kind `2`, stores its target at `+0x10`, clears `+0x14`, and appends it; it does not visibly apply the gate used by `CmdCreateGated`.

## Cancellation, queue movement, and placement

`EntityCommandUnlinkByKind @ 0x00403d10` searches the entity's linked activity list rooted at `entity + 0x2f0` (the decompile accesses it as word `0xbc`) for the requested kind. If found, `param_4` controls unlinking and freeing the record. Kind `7` has an extra coordinate check and may call `FUN_00403700` to mark matching global kind-7 records; kind `0x0c` performs cell-side cleanup and emits callbacks; requested kind `0x17` dispatches an entity activity transition and a UI/event callback. A request for kind `3` also calls `FUN_00403ef0` after the scan. These special cases mean unlink-by-kind is a lifecycle operation, not just list removal. The exact effect of the `FUN_00437cc0`-related callback path is not recoverable from this function alone.

`CommandQueueSweepRelink @ 0x00404100` detaches the entity-local chain and examines each record's flags at `+0x5c`. Records with bit `4` set are freed through `FUN_00406480`. Remaining records are routed back to global head list `DAT_004b3354` when bit `0x10` is set without cancellation bit `0x20`; to global tail list `DAT_004b3358` when bit `0x2000` is set without bit `0x20`; or retained in a rebuilt entity-local chain otherwise. The `0x10` test has priority if both routing bits are present. This routine is used by entity queue flush and append paths, so per-entity commands can be returned to global work queues before the entity chain is updated.

`PlaceCommandEligibilityCheck @ 0x00404fc0` is a predicate with optional coordinate outputs, not a record creator. It clears the optional result flag first; rejects unsupported context records and several entity-state flags; and then applies command-specific checks. Kind `0x1a` checks entity eligibility and placement-specific helpers, with an additional global gate, and may return a derived coordinate pair. Kind `0x1e` requires a resource/placement lookup plus an entity capability bit, then derives coordinates and an optional cell value. Other supported kinds use branches visible in the body (including `0x13`, `0x15`, `0x16`, and `0x17`) to check entity types, flags, target compatibility, or distance and may populate output coordinates. It returns success for some other command kinds after the common rejection gates. The predicate's two final integer arguments change branch behavior; the body does not name those modes, so their intended API contract remains unresolved.

`PendingCommandTimerFireScan @ 0x00405950` walks the global tail list `DAT_004b3358` against the active-entity array at `DAT_004b3428` when the pending entity count is nonzero. For records whose timer at `+0x18` has expired, it evaluates kind-specific gates (visible cases include kinds `4`, `10`, `3`, `0x19`, `0`, `0x1d`, and `0x18`). On a match it removes the pending record from the tail list and either attaches it as the entity's new `+0x2f0` head or passes it through `FUN_00406400`, based on record flag `0x40`; the active-entity array entry is also removed by swap-with-last. Several branches reset the timer instead of attaching immediately. This is a timer-driven assignment path, separate from coordinate-based placement in `PendingCommandEntityAssignmentTick`.

`PendingCommandEntityAssignmentTick @ 0x00405c10` walks the global head list `DAT_004b3354`, selecting eligible, non-expired records and scanning active entities. It checks entity compatibility through `FUN_00452610` or the record's explicit-coordinate form through `FUN_00452650`, then calls `PlaceCommandEligibilityCheck`. For placement-like kinds it validates derived coordinates and nearby-cell/path conditions; when it finds an eligible entity, it compares candidate distance and retains the closest candidate unless an immediate-match branch applies. The selected record is detached from the global list and assigned to the entity via `FUN_00406360`, which either transfers it as the entity-local head or copies it through `FUN_00406400` according to flag `0x40`, then refreshes entity queue state. Other branches handle no-candidate outcomes: type `0x13` can expand through `FUN_004030e0`, and task-kind records may enqueue category work through `FUN_00402890`. The tick also removes processed entities from the active array by swap-with-last. Exact scheduling order and the semantics of all flags require the callers of this tick and the adjacent queue helpers; this body establishes candidate checks and state transitions, not a single universal assignment rule.

## HUD context and entity-status feedback

`CommandContextPostToHud @ 0x0041b2d0` is a three-call wrapper: it invokes `FUN_00435a20`, then `FUN_0041b300(context, value)`, then `FUN_0041ea50(context, value)`. The first visible callee is a pre-update/flush helper; the second updates the selection-resource state for a set of context values and may use the second argument as a coordinate pair; the third helper's behavior is not duplicated here. Call sites submit context values including `9`–`0x15`, often with a null second argument, from interface selection/status handlers. It should not be read as a general gameplay command issuer: the visible state written by `FUN_0041b300` is UI selection/resource state at `DAT_004ddcf4`, `DAT_004ddcf8`, and `DAT_004de1f0`.

`EntityCommandStatusFeedbackDispatch @ 0x00428020` reads the entity's configured status string through `FUN_004395e0`. It suppresses a repeated entity when it is not the current value of `DAT_004de574`, and uses the entity's optional override string at `+8` when present. It copies the selected string into a local buffer, adds a configured suffix for entity kind `4`, and conditionally appends numeric or resource text for other entity states before sending the result through the string-display helpers `FUN_0046b520` and `FUN_0046b700`. Further branches attach per-entity labels/resources. This establishes a stateful status-text presentation path; it does not identify the user-facing text for every entity/config combination.

## Flow summary and limits

The evidence supports two connected but distinct command paths. Some producers allocate typed global task records and link them to the head or tail work list; timer and placement ticks later match those records to active entities and transfer them into entity-local chains. Other producers append records directly to an entity's `+0x2f0` chain, which later sweep/unlink helpers can retain, free, or route back to a global queue. Cell-coordinate producers also update cell state or send callbacks alongside record creation. UI context and status feedback functions expose related player-facing state but are separate from the record-allocation path.

The list heads and several record fields are inferred by repeated direct reads/writes in the assigned functions and their immediate helpers. Names assigned to anonymous helpers and enum meanings beyond explicit call-site values remain uncertain. In particular, this source does not fully establish the scheduling contract of every flag, the two mode parameters to `PlaceCommandEligibilityCheck`, ownership of all records copied by `FUN_00406400`, or the full external meaning of every callback and HUD context value. Finding 256 documents related command-band issuers and timers; Finding 466 is a concurrent PR documenting the shared command registries and links.
