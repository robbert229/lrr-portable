# Preservation controller checkpoint

`~/.local/share/lrr-devbox/ag1-x11/transaction_controller.py serve PRIVATE_DIR CONFIG` accepts a private, owner-only JSON configuration file with exactly `roots` (a nonempty map of simple names to absolute existing directories), `evidence` (an absolute existing owner-only directory), and `allow_symlinks` (boolean). Paths must be canonical, have no symlink components, and be mutually disjoint from one another and the private controller directory. The controller checks directory identities around each worker. Supply a fresh ASCII capability of at least 32 characters on stdin and wait for `READY`; send newline-delimited JSON containing `cap` and `op` to `PRIVATE_DIR/menu-runtime.sock`.

With configuration, `snapshot` creates and authenticates `evidence/snapshot`; `archive` subsequently authenticates that baseline and creates and authenticates `evidence/archive`. The controller holds its lock between requests. A caller may change fixture roots between these operations; runtime launch and stop remain disabled. Success and SHA-256 hashes of the inventory and verification manifests are recorded in the durable incomplete journal. Failure or a wrong phase does not advance the phase; a failed attempt can leave partial evidence and requires manual assessment. Review, restore, verify and complete follow the authenticated archive phase as described below; failures retain the journal. Starting without configuration permits only status and fixture supervision.

The worker uses parent-death signaling, a separate process group and closed inherited descriptors; disconnect or lock replacement stops it. This covers the direct worker, not hostile descendants. Writer exclusion and path identity checks do not prevent noncooperating same-user races. Symlink opt-in preserves link target and atime/mtime during inspection but changes ctime; ctime and inode are excluded from inventories. This checkpoint does not authorize protected runtime use or claim a complete preservation transaction.

Disposable tests: `python3 ~/.local/share/lrr-devbox/ag1-x11/test_real_preservation.py` and `python3 ~/.local/share/lrr-devbox/ag1-x11/test_transaction_controller.py`. They use newly created temporary roots and controller processes. Copies, hashes and logs are retained externally under `~/.local/share/lrr-devbox/ag1-x11/controller-evidence/real-preservation/`.

### Callable preservation seam checkpoint

The external `ag1-x11/preserve.py` exposes `restore(base, after, review_path, result_path, allow_symlinks=False)` with explicit archive and evidence paths, using the roots configured by `snapshot`. It retains the existing review, archive and live-afterstate gates and the final rooted comparison. `verify_live(base, allow_symlinks=False)` authenticates the baseline and returns the rooted diff against configured live roots; callers must inspect the diff. Symlinks require opt-in, with timestamp restoration during inventory; ctime and inode are excluded.

Disposable-root tests exercised changed and added files, attributable review, refusal before mutation, symlink inventory, restoration and independent baseline comparison. Existing snapshot/archive and controller regression tests passed. Exact helper and test source and results are under `ag1-x11/controller-evidence/callable-restore/`. Runtime launch and production identity/input bindings remain disabled for later work.

### Controller restore checkpoint

After archive, `review` accepts a `review` object containing exactly `reviewed_by` (`ag1 sole integrator`), `approved_for_restore` (true), `baseline_manifest_sha256`, `after_manifest_sha256`, and the complete rooted `delta` from the authenticated inventory manifests. The controller validates the payload against both journaled manifest pairs and authenticated archives, atomically persists it and journals its hash. `restore` runs the callable helper in a supervised child; it rechecks evidence and the review and the helper checks the actual afterstate before writing. A separate supervised `verify` invokes `verify_live`, rejects any nonempty rooted diff, and journals the result hash. `complete` requires that result and its hash, removes the journal and controller lock, and exits. The controller processes requests serially and waits for each worker to stop before advancing.

Disposable IPC tests cover the real roundtrip, review rejection, archive corruption, live drift, worker failure, missing verification output and premature completion, as well as the existing preservation and lifecycle regressions. Exact source copies, hashes and logs are in `~/.local/share/lrr-devbox/ag1-x11/controller-evidence/controller-restore/`. The fixture mutation interval is the only enabled interval; launch stays disabled. The same noncooperating-writer and symlink metadata limitations above apply, and menu parity remains open.

The subsequent proc fallback checkpoint did not wire launch or stop into this controller. Archive remains a preservation fixture path and is not an owned-writer gate. See `wine-menu-launch-binding.md` before using any production configuration.

### Fixture controller launch dispatch

The external controller now accepts an optional `launch` object containing `root` and `identities` for `launch_guard.fixture_config`. The root must be a disjoint temporary fixture directory and the dummy make executable must be identity-pinned. After snapshot, `launch` with an allowed `kind` runs a supervised worker that authenticates the journal-bound baseline and rejects any live diff, then invokes the existing supervised fixture launcher. The controller retains the process handle and journals its launch record. `archive` refuses until `stop` observes or terminates and reaps the child and journals its return code. Existing preservation-only configurations continue to work. Production launch remains disabled; input admission and production identity policy are unresolved.

Disposable IPC tests cover baseline drift, executable drift, wrong phase, actual child launch, archive refusal, cleanup and normal exit, and the preservation roundtrip. Existing controller, restore and launcher regressions passed. Copies and hashes of the tested helpers, test and log are in `~/.local/share/lrr-devbox/ag1-x11/controller-evidence/controller-launch-dispatch/`. This closes only the fixture controller lifecycle seam; it does not establish production writer exclusion or menu parity.

### Fixture X11 admission checkpoint

External `input.py` now provides a fixture-only `Admission` object requiring live owned Xvfb and direct client process handles, their Linux starttimes, the Xvfb command-line DISPLAY/authority binding, and an explicit XID. Each operation checks XRes server-reported client PID, process starttime, viewable state, active window and keyboard focus; key names and client-relative click bounds are restricted. Capture records the XID, process and seat identities, geometry, time and PNG hash. The legacy unrestricted input and runtime command entry points are disabled. The adapter requires an isolated seat and serialized callers: X11 checks and input/capture are not atomic, X11 clients can interfere, and authority environment handling is process-global. It is not wired into the controller and does not provide a production Wine process-tree/client identity policy. Production launch remains disabled.

A disposable authenticated Xvfb/Openbox seat and two ordinary Xlib windows demonstrated actual Tab and click receipt, capture, refusal of the other client's window, stale process starttime, invalid key and bounds, focus drift, unmapping and destruction. Owned children were terminated and reaped. Existing launch, preservation, controller and restore fixture regressions passed. Exact helper copies, source, logs, capture and SHA256SUMS are retained at `~/.local/share/lrr-devbox/ag1-x11/controller-evidence/input-admission/`. This is prerequisite fixture evidence, not production or menu parity acceptance.

### Fixture controller X11 input checkpoint

A fixture launch may opt in with `launch.x11: true`. The controller owns a disposable authenticated seat, passes its DISPLAY and XAUTHORITY to the pinned direct fixture child, and retains both child and seat handles. After launch, authenticated `select` takes an explicit `window` XID; `key` takes `key`, `click` takes client-relative `x` and `y`, and `capture` takes a fresh PNG `name` directly under the configured evidence directory. Requests have exact fields. Admission checks XRes ownership, process identities, visibility, active window and focus; action provenance and capture hashes are journaled. Stop closes admission and reaps the client and seat. Normal controller termination also cleans up owned processes. X11 remains a shared-seat, non-atomic interface; production and Wine topology remain unsupported.

The disposable IPC test launches an ordinary Xlib client directly, verifies delivered Tab and click events, capture hash, focus and ownership refusals, and the preservation roundtrip. Sources, binary, journal, capture, logs and hashes are retained in `~/.local/share/lrr-devbox/ag1-x11/controller-evidence/controller-input-ipc/`. This is fixture infrastructure, not menu parity.
