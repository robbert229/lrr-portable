# Menu transaction ownership experiment

2026-11-03. Scratch-only experiment; no runtime lock, protected state, shared helper, Wine, game, build, or child process was touched or started. This does not establish menu acceptance or writer exclusion.

Reproduce with `python3 /tmp/lrr-menu-lock-experiment-1793738537-60257/experiment.py`. The script creates and removes its own disposable fixture below that private scratch directory. Output: PASS for independent descriptor contention, close-on-exec flag, modeled missing/wrong token, dummy phase ordering and retained lock, modeled forged stale state, modeled holder loss, replaced inode detection, symlink rejection, final descriptor close release, and no token output or file write. The scratch directory is temporary and may be cleaned by the system.

The real kernel flock test uses two independently opened descriptors in one process: a second nonblocking exclusive lock is refused while the first is held, and succeeds after its final close. The lifecycle tests assert the contender remains blocked at each dummy phase through verify. Replacement and symlink tests use only disposable paths. `FD_CLOEXEC` is checked, not tested across exec. The authentication, forged state, holder death and loss during a phase are boolean simulations, not real subprocess, PID reuse, crash, in-flight cancellation, or IPC tests. No claim is made that a state file authenticates a holder. The no-child constraint prevented those process-level experiments. The token never appears in script output or fixture files; this does not prove secrecy for a future implementation.

## Small integration recommendation

Choose and document one canonical lock pathname in a private user-owned directory, provisioned once, shared by every cooperative transaction tool. Do not unlink or replace the lock file on release. Open relative to a verified private directory with `O_NOFOLLOW|O_CLOEXEC`, verify regular file, owner, restrictive mode and single link, acquire nonblocking exclusive `flock`, then compare descriptor and pathname device/inode and recheck before each sensitive action. Refuse unsafe or replaced paths. Private directory ownership and a no-replacement convention are essential: pathname comparison cannot prevent a hostile or noncooperative replacement between check and action, and flock alone locks an inode, not a pathname. Do not create or acquire the real lock as part of this experiment.

Run a dedicated controller for the whole snapshot → launch → stop → archive → review → restore → verify sequence. It alone owns the lock descriptor, retains it until verified cleanup completes, and fails closed on error; if cleanup cannot be verified, retain ownership while the controller remains alive and require explicit recovery. A crash releases the kernel lock, so the next owner must detect an incomplete durable transaction journal and refuse normal work until recovery; a lock cannot itself guarantee cleanup after a crash. Do not automatically restore on an uncertain live writer. Preserve the existing game application single-instance mutex unchanged; it is a separate application safeguard and is not held outside the application's lifetime.

For helper admission, use a private Unix-domain control socket owned by the live controller with peer credential checks and a fresh random token delivered over a private inherited pipe or socket, never command line, environment, logs, or persistent state. The holder validates transaction identity, phase, live lock descriptor and pathname before authorizing each operation; do not trust a PID or stale state file. Bind identity to the live connection and, where process identity is needed, a pidfd or PID plus kernel start time, not PID alone. Keep token and authorization out of diagnostics. Deny missing/wrong tokens, stale connections and out-of-order operations. Ensure children cannot inherit the lock descriptor, and supervise helpers: on controller disconnect they must stop safely; the controller must not release while helpers or owned writers remain active. Design bounded operations with checkpoints and fail-closed cancellation, since a check before a long operation does not prevent continuing after ownership loss. Recovery must account for operations interrupted mid-write and for any independently surviving game process.

Before production use, the integrator should exercise actual separate processes and crash/exec scenarios on disposable fixtures: contender exclusion, wrong and missing token, forged journal, killed holder and PID reuse, controller death during each phase, inherited descriptor leak, helper interruption, incomplete-journal recovery, symlink and inode replacement, and secret leakage via argv/environment/logs. Verify that no lock release occurs before stopped writers, archive/review, restoration and verification; force each failure path. Also integrate the existing identity, capacity, process guard and preservation gates independently. No unrelated root `/proc` descriptor inspection is a prerequisite; any inaccessible relevant writer evidence remains an explicit limitation or refusal under the guard's policy.

Advisory flock binds cooperating participants only. Explicit sole human ownership and a scoped process guard remain necessary, and neither proves race-free exclusion of unrelated or noncooperative writers. Inode checks and a private directory reduce accidental replacement but cannot turn the protocol into mandatory locking.
